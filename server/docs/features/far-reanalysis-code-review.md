# #350 재분석 직전 FAR 시간 보존 독립 리뷰

개입과 분석 예약 경계를 별도 컨텍스트에서 검토했다. 같은 요청의 재시도와 늦은 분석 완료는 기존 관측 순서 검증을 따른다.

## 1. Medium — 동의를 철회하기 전 판정으로 FAR 누적을 재개할 수 있음

동의 철회가 FAR 체크포인트를 멈춰도 정책 타임라인의 마지막 판정이 살아 있었다. 같은 전경에서 재동의하면 heartbeat가 이전 판정을 다시 열고 다음 재분석이 그 시간을 확정할 수 있었다.

무효화 시 현재 판정 ID와 시각을 지우고 연속 구간을 닫는다. 과거 반복 구간은 기존 규칙대로 보존한다. 별도 유효 플래그를 추가하는 방법도 검토했으나 기존 현재 판정 필드로 충분했다. 철회 후 heartbeat와 새 본문 판정의 재개를 검증한다.

## 2. Low — 재분석 예약과 10분 경계의 통합 검증 부족

초기 테스트는 분리된 서버 시각으로 누락 구간과 AI 대기를 검증했다. 실제 저장 경로의 재분석 예약에서 누적 10분에 도달하고, 중복 요청을 거부하고, 판정 확정 뒤 제안 한 건을 생성하는 테스트를 추가했다.

## 3. Medium — Chrome 제목이 유지된 페이지 전환에서 누적이 앞당겨짐

Desktop의 전경 context가 같은 Chrome 창 제목을 유지하면 Extension만 URL 이동을 알 수 있다. 새 요청은 15초 체류 뒤에 도착한다. 동일 context라도 Extension의 새 TAB_META 또는 CHROME_DOM은 앞 페이지와 이어진 증거가 아니므로 예약 시 FAR 체크포인트를 합산하지 않고 닫는다. Desktop 기기의 직전 OCR과 새 Desktop 관측에만 예약 시 합산을 적용한다.

10분 기준 직전의 예전 Chrome FAR에 같은 context·제목·호스트의 다음 TAB_META와 CHROME_DOM을 보내는 서버 회귀를 추가했다. 기존 구현에서 590초가 600초까지 올라가는 것을 재현했다. 정확한 페이지 전환 직후부터 heartbeat의 계산을 멈추려면 클라이언트가 전환을 알려야 한다.
