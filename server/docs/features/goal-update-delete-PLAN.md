# 목표 수정·삭제 구현 계획

- Issue: #97
- Branch: `feat/97-goal-update-delete`, 기준 `origin/dev` 7811667
- 범위: 본인 목표 수정·soft delete, 활성 세션 참조 차단, Swagger 및 검증

## 계약과 처리

- `PATCH /api/v1/goals/{goalId}`: `goalText`를 기존 목표 생성과 같은 공백 제거·2~40 Unicode 코드 포인트 규칙으로 검증하고 수정된 목표를 반환한다.
- `DELETE /api/v1/goals/{goalId}`: 목표를 물리 삭제하지 않고 `deletedAt`을 기록하며 204 빈 본문을 반환한다.
- 존재하지 않거나 다른 사용자 소유이거나 이미 삭제된 목표는 기존 조회와 같은 404로 처리한다. 활성 세션이 참조 중이면 409 `GOAL_UPDATE_BLOCKED`다.
- 세션 시작과 같은 사용자 행 잠금을 먼저 얻고 목표와 활성 세션을 확인한다. 잠금은 트랜잭션 종료까지 유지한다.
- 세션의 목표 스냅샷은 건드리지 않는다. 목표 명확화, 목록과 세션 API 개발은 제외한다.

## 검증 계획

- 인증, 소유권, 길이, 수정·재조회, soft delete·반복 삭제, 활성/종료 세션, 동시 요청을 검증한다.
- Swagger, 빌드·Checkstyle과 PostgreSQL 동시성 검증 결과를 분리해 REPORT에 기록한다.
- Notion 상세 항목을 직접 확인하지 못한 경우 미확인으로 기록하고 계약 변경을 추측하지 않는다.
