# #347 목표 버전 변경과 개입 독립 리뷰

최신 dev 기준으로 정책 잠금, 이전 분석 완료와 heartbeat, 기존 JSON, 미전송 개입 조회, receipt와 cooldown 의미를 검토했다.

## 1. Low — 실제 할 일 변경과 전송 확인 경로 검증 부족

기존 회귀는 DB에서 직접 목표 버전을 변경하므로 실제 할 일 추가 API에서 개입까지 이어지는 경로를 검증하지 않았다.

기존 개입 통합 테스트가 할 일 추가와 heartbeat의 정상 경로를 호출하도록 보완했다. 이전 버전의 휴식 제안 차단과 늦은 SENT의 만료 유지, 동일 receipt 재시도, 기존 5분 cooldown도 검증에 넣었다. 실기기 QA로 대체하는 방법은 전송 표시까지 확인할 수 있으나 반복 실행이 어려워 이번에는 서버 통합 테스트로 확인했다.

그 밖의 Critical·High·Medium 지적은 없었다. 이전 개입의 전송 여부가 불명확하면 후속 개입을 보류하는 기존 규칙을 적용한다.
