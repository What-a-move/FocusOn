# 학습 정리 근거 수신 독립 리뷰

구현 대화와 분리된 에이전트가 기능 diff, 기획서, API·개인정보·코드 규칙을 검토했다. 리뷰는 정적으로 진행했으며 실행 결과는 QA 문서에 기록한다.

## 1. 🟡 Medium — URL의 일부 형식이 라벨 검사를 통과

**문제** — `AnalysisPrivacy`의 URL 검사가 `://`와 `www.`만 탐지해 스킴 상대 URL과 `file:/`, `data:` 형식이 내부 판정에 들어갈 수 있었다.

**해결 방안** — 적용한 방법은 URL 형태를 추가로 거절하고 회귀 사례를 추가하는 것이다. 공유 민감정보 검사로 통합하는 방안도 있으나 다른 API의 검증 동작과 배포 순서에 영향을 줄 수 있다.

## 2. 🟡 Medium — 통합 테스트의 지연 로딩 의존

**문제** — `AnalysisApiTests`가 테스트 스레드의 저장소 호출 트랜잭션 밖에서 목표 엔티티의 ID를 읽었다.

**해결 방안** — 적용한 방법은 기존 fixture의 트랜잭션에서 목표 ID를 반환하는 것이다. ID 전용 조회나 별도 트랜잭션으로 가져오면 fixture 변경은 줄지만 추가 조회가 필요하다.

## 3. 🟢 Low — 보이는 본문이 없는 관측에서 근거 수신

**문제** — `AnalysisAiClient`의 `String.isBlank()` 검사에는 줄바꿈 없는 공백(U+00A0)이 포함되지 않는다.

**해결 방안** — 적용한 방법은 근거 수신에만 유니코드 공백·제어·형식 문자 검사를 적용하는 것이다. AI의 추출 상태 계산까지 같은 규칙으로 바꾸면 로직을 공유할 수 있으나 기존 화면 판정도 바뀔 수 있다.

Critical 및 High 지적 사항은 없었다.

PR #369의 CodeRabbit 검토에서 괄호 안의 스킴 상대 URL이 통과하는 사례를 추가로 찾았다. 후속 독립 리뷰에서 일반 연산자도 거절될 수 있음을 확인해 구두점과 공백을 URL 시작 경계에 포함했다. 괄호 안 URL은 폐기하고 `a//b` 연산자 표기는 받는 회귀 사례를 추가했다.
