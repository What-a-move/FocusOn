# 서버 요청 추적과 구조화 로그

- Issue #116; 사용자 승인 범위: 요청 추적과 개인정보를 제외한 로그. 분석 API·가짜 판정기는 제외한다.
- 기존 서버 발급 requestId를 유지하고, 유효한 단일 `X-Trace-Id`만 수용한다. 누락·중복·형식 오류는 UUID로 대체한다. 응답 헤더와 MDC를 설정하고 finally에서 정리한다.
- `http.in`/`http.out`은 한 필터에서 기록하고 소요 시간은 단조 시계 차이로 구한다. 원본 URI는 민감한 경로 변수를 포함할 수 있으므로 안전하게 정의된 경로만 기록하고 미등록 경로는 마스킹한다.
- 성공·인증 오류·404·예외 및 동시 요청을 검증한다. traceId를 인증이나 저장 키에 사용하지 않는다.
- 검증 오류의 필드명과 기대 타입은 프레임워크가 제공하고 안전하게 판별 가능한 경우에만 기록한다. 입력값·본문·인증정보·query·예외 원문은 기록하지 않는다.
- Spring Boot 내장 logstash JSON을 사용한다. 실제 JSON 필드·개인정보 비노출·MDC 복원을 검증한다.
- Notion 로깅 정본은 연결 도구의 404 이후 로그인된 브라우저에서 직접 읽었다. 정본의 공통 필드(`ts`, `module`, `component`, `event`, `traceId`, `durMs`)를 대조한다. 정본의 UUID 형태 설명보다 구체적인 수신 정규식은 사용자가 직접 확정한 `[A-Za-z0-9-]{8,64}`를 따른다.
- 테스트: 정상/누락/잘못된/중복 traceId, requestId 독립성, 필터 예외, 로그 필드·민감정보 차단, 인증·404 회귀 및 전체 build.
