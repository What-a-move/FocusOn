# 세션 Heartbeat 결과

## 기본 정보

- Issue #167, `feat/167-session-heartbeat`, 2026-11-07.
- 사용자 제공 세션 설계·상태 전이 정책을 대조했다. Notion 페이지 자체는 접근하지 못했다.

## 구현 결과

- `POST /api/v1/sessions/{sessionId}/heartbeats`: 사용자·Desktop 기기·헤더 검증, 관측 순서·누적 시간 검증, 상태 응답과 목표 도달 전이.
- V13에서 마지막 클라이언트 관측 시각을 추가하고 서버 수신 시각과 분리했다. 동일 관측과 진행 없는 과거 관측은 무시하며, 시계 역행 시 증가한 누적 시간은 검증 후 수용한다.
- 60초는 상태 변경 없는 후보, 180초는 마지막 확인 시간만 보존하며 `ABANDONED` 확정. 10초 주기 worker와 늦은 신호에서도 조건을 확인한다.
- 일반 heartbeat는 버전을 유지하고 목표 도달·자동 종료는 버전을 증가시킨다. 사용자 잠금과 세션 행 잠금, 조건부 UPDATE로 경합을 제어한다.
- 요청 빈도는 기존 인증 사용자·기기별 분당 60회 제한을 공유한다. 미정 세부 기준은 이슈 댓글에 기록했다.

## 검증

- `./gradlew clean build`: H2 136건 중 실패 0·오류 0·건너뜀 5, Checkstyle 통과. 건너뜀에는 PostgreSQL 전용 대기 검증이 포함된다.
- 격리 PostgreSQL 17에서 `SessionApiTests` 13건 실패 0·건너뜀 0. 동일·역순·누적 감소·소유권·목표 도달·후보/종료·429·경쟁을 확인했다.
- PostgreSQL `pg_blocking_pids`의 재귀 대기 체인으로 heartbeat와 worker가 같은 사용자 행 잠금을 실제로 기다리는 것을 확인했다.
- 별도 PostgreSQL DB에서 V10 상태의 기존 세션 1건(누적 12345, 버전 3)을 만든 후 Flyway V11 적용 전후 상태·버전·누적 시간 보존과 새 필드 NULL을 확인했다.
- 격리 HTTP 서버에서 합성 JWT 인증 `GET /auth/me` 200, heartbeat 정상 200, 같은 관측 재전송 200 및 값 보존, 감소 400을 확인했다. 실제 Google 계정 인증이 아니다.
- 당시 Google PKCE 브라우저 인증은 90초 대기 후 시간 초과됐다. 이후 재검증 결과는 아래에 기록한다.

### 2026-11-08 재검증

- 격리 PostgreSQL 17에서 SessionApiTests 13건 전체 통과. 실제 사용자 행 잠금 대기 및 heartbeat·정리 작업 경합 테스트를 포함한다.
- 사용자가 Google 인증한 계정으로 8080 서버에 실제 HTTP 요청을 보냈다. Google exchange 201, 테스트 목표·세션 생성 201, heartbeat 200, 동일 관측 재전송 200과 수신 시각 유지, 기기 헤더 누락 400을 확인했다. 이번 실계정 요청의 누적 시간은 0ms였으며 시간 증가 시나리오는 자동 테스트로 확인했다.
- 테스트 목표와 세션이 사용자 개발 DB에 생성됐다. 실행 중 서버는 #177 Google 로그인 수정이 적용된 상태였고 소스 브랜치는 #167이므로 두 브랜치의 통합 검증과 구분한다. Swagger UI 조작 및 Desktop·Extension 전체 통합은 별도다.
- 최신 dev `91cd524`를 통합하고 확장 연결 V11·V12 다음으로 Heartbeat migration을 V13으로 조정했다. 통합 후 전체 build·Checkstyle, 격리 PostgreSQL에서 Flyway V1~V13 및 SessionApiTests 13개가 통과했다.
- 사용자 개발 DB에 과거 Heartbeat V11이 이미 적용된 이력이 있어 최신 dev의 확장 연결 V11과 충돌한다. 해당 DB는 수정하거나 초기화하지 않았다. 데이터 보존 여부와 이력 처리 방안을 확인하기 전 이 DB로 통합 버전을 실행하지 않는다. 새 DB에서의 V1~V13 검증이 기존 DB 업그레이드 검증을 뜻하지는 않는다.

## 남은 작업

- Swagger UI에서 정상·권한·오류 사례를 검증하고, Notion API 정본의 필드·오류와 대조한다. #177 로그인 수정과 #167의 통합 상태를 확인한다.
- #163 세션 종료 변경과의 연계 및 기존 개발 DB의 Flyway 이력 처리 방안을 확인한다.

### PR #178 리뷰 대응

- 잠긴 사용자 건너뛰기, 후보별 실패 격리, 시계 역행 시 누적 시간 증가를 통한 복구를 반영했다. 페이지를 나눠 앞쪽 잠긴 후보들이 뒤쪽 후보를 가로막지 않게 했다.
- 격리 PostgreSQL에서 잠긴 사용자 뒤의 만료 세션이 먼저 종료되고 잠금 해제 후 남은 세션이 종료되는지 확인했다. 후보 선택 뒤 신호가 갱신되면 조건부 종료가 실패하는 테스트도 추가했다.
- 이미 반영된 동일 재전송은 생존 시각을 늘리지 않는다. 이전에 처리되지 않은 지연 신호와 시계 역행 신호는 별도 순번이 없어 완전히 구분할 수 없다.
