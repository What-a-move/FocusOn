## 목적과 API

세션 종료 전에 접수한 분석이 종료 후 30초 안에 완료되면 정제된 학습 개념을 복습 노트 입력에 포함한다. 종료 API는 바로 응답하고, 분석 API는 종료 뒤 완료에도 기존 상태 및 응답 형식을 사용한다. 분석 이력·개입·집중 시간에 종료 후 학습 근거를 반영하지 않는다.

## 저장 조건

- 종료 전에 서버가 RUNNING으로 접수하고 최종 `RELATED + MATCHED`로 정규화된 DOM·OCR 분석의 기존 정제 개념 형식을 사용한다.
- 기기 연결·소유권·동의와 제외·보호 조건을 완료 시 다시 검증한다. 접수 대비 필수 동의 버전 또는 승인 시각이 달라졌거나, 목표 버전이 변경되었거나, 해당 기기의 현재 관측보다 이전이면 종료 후 근거에서 제외한다.
- 사용자 종료 시 정리 행에 마지막 실행 구간 시작 시각을 고정한다. 접수 구간과 일치해야 한다. 일시정지 상태 종료, 이전 실행 구간에서 시작된 분석, ABANDONED, 실행 구간이 없는 기존 생성 행은 종료 후 근거를 받지 않는다. 목표 시간 도달 뒤 같은 구간에서 종료를 확정하는 경우를 포함한다.
- 기존 동의 모델과 정제·중복 제거·보관 기한을 적용한다. 화면 원문·제목·URL·인증 정보는 저장하지 않는다.

## 동시성·데이터

생성 작업의 행 잠금을 획득한 뒤 최초 `QUEUED` 상태, 실행 구간과 기존 `input_cutoff_at`을 검사한다. Worker의 첫 입력 점유와 같은 행에서 저장을 직렬화한다. 쓰기를 플러시한 시점이 마감을 지났으면 그 근거를 제거한 뒤 커밋한다. 이미 점유했거나 재시도 대기 중인 작업의 입력은 변경하지 않는다.

`learning_summaries`에 내부용 nullable 실행 구간 시각을 추가한다. 팀원 PR #390이 V39를 사용하므로 V40으로 작성하고 PR 제출 시 최신 dev와 마이그레이션 순서를 재확인한다.
