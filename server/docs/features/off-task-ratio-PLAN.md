# 최근 10분 이탈 비율 기반 포키 알림

## 기본 정보

- 관련 이슈 [#342](https://github.com/What-a-move/FocusOn/issues/342)
- 브랜치 `feat/342-server-off-task-ratio`
- 우선순위 MVP 핵심

## 목적과 범위

- 담당 영역은 Backend 분석·개입이다. DR-024~030의 v2 이탈 비율 조건을 기존 OFF_TASK 생성 경로에 추가한다.
- 기존 최신 관측, 보호 상태, heartbeat, 실제 전송 cooldown, 중복 방지 경로를 재사용한다.
- 공개 API·클라이언트·AI 계약은 그대로 사용한다.

## 데이터와 계산

- 기존 `timeline_json`의 무관 구간과 새 관련 시간 조각을 같은 최근 10분 경계로 자른다. 관련 시간 조각은 서버 시각만 저장한다.
- 검증용 분모는 창의 확정 RELATED + UNRELATED 시간이다. 처리 대기, 불확실·보호·미관찰 시간은 세지 않는다. 15초 미만의 확정 UNRELATED 구간은 비율 집계에서 빼고, 현재 확정 UNRELATED 구간도 15초 이상일 때만 후보를 만든다. 구간이 10분 경계에 걸치면 창 안의 시간만 세고 열린 구간은 한 번만 센다.
- 오래된 JSON은 처음 수집하는 시점부터 두 판정의 시간을 같은 기준으로 세며 과거 기록을 추정하지 않는다.
- Notion 정본 조회는 404였다. `FOCUSON_OFF_TASK_RATIO_PERCENT`와 `FOCUSON_OFF_TASK_RATIO_MINIMUM_OBSERVED_SECONDS`는 모두 0이 기본이다. 두 값을 함께 지정한 환경에서만 관련 시간 조각을 새로 수집하고 후보를 평가한다. 각각 1~100%, 1~600초 범위이며 기준과 같을 때 충족한다. 실제 적용 값과 분모는 제품 계약 확인 후 확정한다.
- v1과 기존 v2 연속·반복 조건을 유지한다. 최신 판정이 현재 목표 버전과 다르면 비율 조건을 적용하지 않는다. 같은 실행 구간에서 확인한 관측만 합산하며 재개하면 새로 수집한다.

## 연동

- 기존 개입 조회 및 전송 확인 계약을 사용한다. 공개 요청·응답, ERD migration, 클라이언트·AI 수정 사항은 없다.

## 검증

- 비활성 기본값, v1 호환, 최근 10분 경계, 관측 부족, 판단 대기·보호, 쿨다운, 기존 JSON, 실제 이벤트 생성과 재요청을 검증한다.
