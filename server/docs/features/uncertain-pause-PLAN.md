## 기능 목적

- 해결할 문제: 확정 규칙은 "판단 보류(UNCERTAIN) 시간은 쌓지도 빼지도 않고, 분석 장애는 사용자 행동으로 세지 않는다"이다. 지금 `OffTaskTimeline`은 UNRELATED가 아닌 결과가 오면 열린 딴짓 구간을 닫아, 딴짓 → 판단 보류 → 딴짓에서 연속 시간이 0부터 다시 쌓인다.
- Backend가 담당할 역할: 서버 정책 상태(`intervention_policy_states.timeline_json`)의 구간 계산만 바꾼다.

## API 정의

- 공개 Endpoint·요청·응답 형식 변경 없음.
- 새 세션의 `interventionPolicyVersion`과 분석 기록·개입 이벤트의 `policyVersion` 값이 `v2`가 된다(문자열 필드, 클라이언트는 값을 해석하지 않음).

## 데이터 설계

- 마이그레이션 없음. 타임라인 snapshot 구조도 그대로다(열린 구간을 유지하고 시간 조각만 닫음).

## 처리 흐름

1. 분석 완료(`InterventionPolicyService.completed`)가 세션의 정책 버전을 `OffTaskTimeline.complete`에 넘긴다.
2. v2에서 결과가 UNCERTAIN이면 현재 시간 조각만 닫고 열린 구간 번호(`openEpisode`)는 유지한다.
3. 다음 UNRELATED는 같은 구간 번호로 새 시간 조각을 연다. 연속 시간은 같은 구간 조각의 합이라 보류 시간은 빠진다.
4. RELATED·보호 상태·실행/context 전이는 지금처럼 구간을 끊는다.
5. v1 세션은 기존 동작을 유지한다. 알림 조건 표(강도별 연속·반복)는 v1과 같다.
