# 문장 작성 규칙

기획서, Issue, PR, 오류 기록에서 같은 의미를 같은 표현으로 사용한다.

## 기본 규칙

- 한 문장에는 하나의 의미만 작성한다.
- 주어와 행동을 분명하게 작성한다.
- `빠르게`, `적절하게`, `최대한` 같은 모호한 표현은 기준과 함께 쓴다.
- 확정된 내용과 검토 중인 내용을 구분한다.
- 개발자가 아닌 팀원도 이해할 수 있도록 전문 용어를 처음 사용할 때 설명한다.

## 상태 표현

| 나쁜 표현 | 권장 표현 |
| --- | --- |
| 분석을 잘한다 | 페이지 제목과 목표 문장을 비교해 관련성 점수를 반환한다 |
| 나중에 처리한다 | 2차 개발에서 처리한다 |
| 오류가 조금 있다 | 특정 도메인 이동 시 15초 재분석 요청이 중복 발생한다 |
| 카메라를 적당히 사용한다 | 사용자가 동의한 세션에서만 카메라 분석을 실행한다 |

## 알림 문구

알림은 짧고 상황을 설명하되 사용자를 모욕하거나 성격을 판단하지 않는다. 반복 이탈을 안내할 때는 이전 상황과 현재 행동을 연결할 수 있지만, 협박·비난·조롱 표현은 사용하지 않는다.

```text
현재 화면이 설정한 목표와 조금 달라 보여.
잠깐 확인하고 다시 집중해볼까?
```

## 두더지 피드백 문구

집중 상태:

```text
잘 하고 있어!
조금씩 목표에 가까워지고 있어.
오늘의 흐름이 좋아.
```

집중 이탈 상태:

```text
지금 화면이 설정한 목표와 조금 달라 보여. 다시 확인해볼까?
아까도 이 페이지에서 흐름이 끊겼어. 계속 볼지 학습으로 돌아갈지 선택해줘.
잠깐 쉬는 중이라면 타이머를 멈춰도 괜찮아.
```

문구는 상황에 따라 바꿀 수 있지만, `집중하지 못하는 사람`처럼 사용자를 단정하는 문장은 사용하지 않는다.
