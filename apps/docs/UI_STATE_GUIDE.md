# UI 상태 가이드

모든 비동기 화면은 정상 상태만 만들지 않고 다음 상태를 함께 설계한다.

| 상태 | 화면에서 보여줄 내용 |
| --- | --- |
| 초기 | 기능 목적과 시작 방법 |
| 로딩 | 진행 중인 작업과 중복 클릭 방지 |
| 성공 | 최신 데이터와 가능한 다음 행동 |
| 빈 상태 | 데이터가 없는 이유와 생성 방법 |
| 오류 | 실패 원인 범위와 재시도 방법 |
| 권한 거부 | 사용할 수 없는 기능과 권한 설정 방법 |
| 연결 끊김 | 마지막 동기화 상태와 재연결 방법 |

## FocusOn 필수 상태

- 로그인 전과 로그인 만료
- 진행 중인 학습 세션 없음
- 세션 실행·일시정지·완료
- Desktop과 Extension 연결 전·연결 중·연결 끊김
- 카메라와 화면 기록 권한 허용·거부
- 분석 제외 앱 또는 도메인
- Server 응답 지연과 네트워크 끊김

## 문구 원칙

- 사용자를 비난하거나 집중 상태를 단정하지 않는다.
- 무엇이 발생했는지와 사용자가 할 수 있는 행동을 함께 안내한다.
- 단순히 `오류가 발생했습니다`로 끝내지 않는다.
- 같은 상태는 Desktop과 Extension에서 같은 용어로 표시한다.

## 접근성

- 접근성은 선택 사항이 아니라 모든 UI 작업의 기본 완료 조건이다.
- 색상만으로 성공·경고·오류를 구분하지 않는다.
- 버튼과 입력 요소는 키보드로 이동하고 실행할 수 있어야 한다.
- 의미 있는 버튼과 입력 요소에 접근 가능한 이름을 제공한다.
- 텍스트와 배경의 읽기 가능한 대비를 확인한다.
- Focus 표시를 이유 없이 제거하지 않는다.
- 로딩 상태가 끝나면 버튼의 사용 가능 상태도 함께 복구한다.
