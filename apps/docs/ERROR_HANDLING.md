# Frontend 오류 처리 규칙

## 목표

오류가 발생해도 Desktop 앱, Chrome 페이지, 학습 세션이 함께 멈추지 않도록 한다.

## 오류 분류

| 분류 | 예시 | 사용자 처리 |
| --- | --- | --- |
| 입력 오류 | 잘못된 목표 시간 | 수정할 항목 안내 |
| 권한 오류 | 카메라·화면·Chrome 권한 거부 | 설정 방법과 제한 기능 안내 |
| 연결 오류 | Server·Desktop 연결 끊김 | 마지막 상태와 재연결 제공 |
| 인증 오류 | 로그인 만료 | 다시 로그인 안내 |
| 시스템 오류 | 알 수 없는 예외 | 안전한 기본 화면과 재시도 제공 |

## 코드 규칙

- `catch`에서 오류를 무시하지 않는다.
- 외부 오류는 UI가 이해할 수 있는 공통 오류 모양으로 변환한다.
- 사용자 문구와 개발 로그를 분리한다.
- 사용자가 해결할 수 없는 내부 메시지와 Stack Trace를 화면에 그대로 노출하지 않는다.
- 오류가 발생해도 분석 중지, 카메라 종료, 이벤트 해제 같은 정리 작업은 수행한다.

## 로그 금지 정보

- 인증 토큰과 쿠키
- 비밀번호와 결제 정보
- 원본 카메라 영상과 화면
- 페이지 본문 원문과 개인 메시지
- URL Query에 포함된 개인 식별값

원문 대신 다음과 같은 최소 정보만 기록할 수 있다.

- 본문 길이
- 수집 성공 여부
- 분석 결과 코드
- 민감 정보를 제거한 도메인 분류

기능 개발 중 실제 오류가 발생하면 대상 앱의 `docs/features/기능명-오류명-ERROR.md`에 오류별로 기록한다. 오류가 없으면 ERROR 문서를 만들지 않는다.
