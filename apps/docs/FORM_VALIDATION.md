# Frontend Form 검증 규칙

## 목적

Form Validation은 사용자가 입력한 값이 사용할 수 있는 형태인지 확인하는 과정이다. Frontend 검증은 빠른 안내를 담당하고 Server 검증은 최종 안전성을 담당한다.

## 기본 원칙

- Frontend 검증을 통과해도 Server에서 다시 검증한다.
- Server 오류를 Field 오류와 Form 전체 오류로 구분한다.
- 사용자가 입력하기 전부터 오류를 표시하지 않는다.
- 오류 문구에는 문제와 해결 방법을 함께 적는다.
- Button 비활성화만으로 오류 이유를 숨기지 않는다.
- 입력 원문과 인증 정보를 Log에 기록하지 않는다.

## FocusOn 입력 대상

| 입력 | 확인할 항목 |
| --- | --- |
| 학습 목표 | 필수 여부, 길이, 공백만 입력 |
| 학습·휴식 시간 | 숫자 범위, 단위, 시작·종료 관계 |
| 응원·경고 문구 | 길이, 금칙어, 빈 값 |
| 제외 앱 | Bundle Identifier 형식과 중복 |
| 제외 Domain | Protocol 제거, Domain 형식, 하위 Domain 정책 |
| 연결 Code | 길이, 만료, 사용 완료 여부 |

정확한 제한값은 기능 PLAN과 Server API 계약에서 확정한다.

## 검증 시점

- 입력 중에는 사용을 방해하지 않는 최소 안내만 제공한다.
- Blur 시 해당 Field를 검증할 수 있다.
- Submit 시 전체 Form을 검증한다.
- Server 응답 후 Server 검증 오류를 알맞은 Field에 연결한다.

## 접근성

- Label과 Input을 연결한다.
- 오류 문구가 어떤 Input의 오류인지 연결한다.
- 오류 발생 시 키보드 Focus 이동을 방해하지 않는다.
- 색상만으로 오류를 표시하지 않는다.

## 도구 결정

React Hook Form, Zod 같은 도구는 아직 확정하거나 설치하지 않는다. 실제 첫 Form의 요구사항을 확인한 뒤 사용자와 비교하고 선택한다.
