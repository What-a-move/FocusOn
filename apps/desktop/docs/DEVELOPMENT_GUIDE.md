# Desktop 개발·학습 가이드

> 이 문서는 macOS Desktop Renderer를 개발하면서 Next.js, Tailwind CSS, TypeScript를 함께 익히기 위한 실무 기준이다.
> 코드는 지금 동작하는 것만 목표로 하지 않고, 다음 담당자가 쉽게 읽고 고칠 수 있는 상태를 목표로 한다.

## 1. 학습을 병행하는 개발 원칙

기능을 하나 만들 때마다 관련된 기술 개념을 하나 이상 확인한다.

| 기술 | 이번 작업에서 확인할 질문 | 쉬운 설명 |
| --- | --- | --- |
| Next.js | 이 파일은 서버 컴포넌트인가, 클라이언트 컴포넌트인가? | 서버 컴포넌트는 미리 준비하는 화면이고, 클라이언트 컴포넌트는 사용자의 클릭에 반응하는 화면이다. |
| Tailwind CSS | 이 클래스가 어떤 크기·색상·간격을 만드는가? | CSS 속성을 작은 조립 블록처럼 붙여서 화면을 만드는 방식이다. |
| TypeScript | 이 값의 모양과 가능한 상태를 타입으로 설명했는가? | 함수나 데이터에 “어떤 모양의 상자만 받는다”고 라벨을 붙이는 것이다. |

작업 설명이나 결과 리포트에는 다음 세 가지를 짧게 남긴다.

- 이번에 새로 배운 문법 또는 개념
- 그 문법을 이 위치에서 사용한 이유
- 다음에 비슷한 코드를 작성할 때 주의할 점

## 2. 코드 주석 기준

### 주석을 작성해야 하는 경우

- TypeScript 문법이 처음 보는 사람에게 어려운 경우
- Next.js의 서버·클라이언트 경계처럼 동작 이유가 코드만으로 드러나지 않는 경우
- Electron Main·Preload·Renderer 사이의 경계와 데이터 전달 이유를 설명해야 하는 경우
- macOS 권한, 화면 캡처, 카메라 생명주기처럼 운영체제 제약이 있는 경우
- 임시 우회가 아니라 유지해야 하는 업무 규칙이나 보안·개인정보 판단이 있는 경우
- 재사용 함수나 컴포넌트의 입력값, 반환값, 사용 목적을 설명해야 하는 경우

### 주석을 작성하지 않아도 되는 경우

- 변수 이름만 읽어도 의미가 분명한 단순 코드
- 코드를 그대로 번역한 설명
- 시간이 지나면 틀릴 가능성이 높은 구현 세부사항

주석은 **짧고 한국어로** 작성한다. 주석보다 좋은 이름과 작은 함수가 먼저다.

```tsx
'use client'

import { useState } from 'react'

export function StudyButton() {
  // [학습] useState는 화면에서 바뀌는 값을 기억하고, 값이 바뀌면 화면을 다시 그린다.
  const [isStudying, setIsStudying] = useState(false)

  return (
    <button type="button" onClick={() => setIsStudying((current) => !current)}>
      {isStudying ? '학습 일시정지' : '학습 시작'}
    </button>
  )
}
```

```ts
type StudySession = {
  id: string
  startedAt: string
  status: 'idle' | 'running' | 'paused' | 'completed'
}

// [유지보수] 세션 상태를 한곳에서 관리하면 화면과 Electron 연결 코드가 서로 다른 값을 기대하는 실수를 줄일 수 있다.
function getSessionLabel(session: StudySession): string {
  const labels: Record<StudySession['status'], string> = {
    idle: '대기 중',
    running: '학습 중',
    paused: '일시정지',
    completed: '완료',
  }

  return labels[session.status]
}
```

`[학습]`, `[유지보수]`, `[주의]`처럼 목적이 드러나는 표시를 사용할 수 있다. 단, 모든 줄에 주석을 붙이지 말고 **어려운 부분과 판단이 필요한 부분에만** 작성한다.

## 3. TypeScript 작성 규칙

TypeScript는 데이터 모양을 미리 알려주는 안전벨트다. 처음에는 복잡한 타입보다 읽기 쉬운 타입을 우선한다.

- `any`는 사용하지 않는다. 정말 모르는 값은 `unknown`으로 받고 확인한 뒤 사용한다.
- 외부에서 들어오는 데이터는 타입을 만든다. 예: Electron IPC 메시지, Server API 응답, 컴포넌트 props.
- 함수 매개변수와 반환값을 읽는 사람이 알 수 있게 작성한다. 반환값이 명확한 간단한 함수는 TypeScript 추론을 허용한다.
- 값이 여러 상태를 가질 때는 문자열을 넓게 열어두지 말고 유니온 타입을 사용한다.
- `null`이나 `undefined`가 될 수 있는 값은 사용하는 곳에서 먼저 확인한다.
- 타입 오류를 무시하려고 `as`를 남발하지 않는다. 데이터가 정말 그 타입인지 확인하는 과정을 먼저 둔다.
- 여러 화면에서 공유하는 타입은 `packages/shared-types`에 두고, Desktop 화면에만 필요한 타입은 해당 기능 가까이에 둔다.
- 타입 이름은 데이터의 역할이 보이게 짓는다. `Data`, `Info`, `Result`처럼 너무 넓은 이름은 피한다.

## 4. Next.js 작성 규칙

- 기본은 서버 컴포넌트로 생각하고, `useState`, `useEffect`, 클릭 이벤트처럼 브라우저에서 실행되어야 할 때만 `'use client'`를 사용한다.
- `'use client'`를 파일 상단에 추가하면 그 파일과 하위 컴포넌트가 브라우저 코드가 될 수 있으므로 범위를 작게 유지한다.
- 페이지(`app/**/page.tsx`)는 화면 조립에 집중시킨다. 복잡한 데이터 변환·IPC 호출은 별도 함수나 컴포넌트로 분리한다.
- Node.js API와 Electron API는 정적 Export된 Renderer 화면에서 직접 사용할 수 없을 수 있다. Preload가 노출한 안전한 API를 통해 접근한다.
- 로딩·오류·빈 상태를 처음부터 고려한다. 사용자가 보는 상태와 내부 상태 이름을 일치시킨다.
- 컴포넌트는 “무엇을 보여주는가”가 이름에 드러나도록 만든다. 예: `StudySessionCard`, `PermissionStatus`.

## 5. Tailwind CSS 작성 규칙

Desktop은 Tailwind CSS v4를 사용한다. `postcss.config.mjs`에서 `@tailwindcss/postcss`를 연결하고, `app/globals.css`에서 `@import 'tailwindcss';`를 한 번만 불러온다. 화면 스타일은 컴포넌트의 `className`에 작성한다. Production build는 Electron 정적 Export의 재현성을 위해 `next build --webpack`을 사용한다.

- 클래스가 길어져 읽기 어려우면 컴포넌트를 분리한다. 한 줄을 억지로 줄이는 것보다 역할을 나누는 것이 유지보수에 좋다.
- 같은 UI 스타일이 세 번 이상 반복되면 공통 컴포넌트나 재사용 가능한 스타일로 만든다.
- 색상·간격·글자 크기는 프로젝트의 디자인 토큰을 우선 사용한다. 화면마다 임의의 값을 만들지 않는다.
- macOS 창 크기와 화면 배율을 고려한다. 고정된 크기만 믿지 말고 작은 창에서도 내용이 잘리지 않는지 확인한다.
- 조건부 클래스는 상태 이름이 먼저 보이게 작성한다. 예: `isStudying ? activeClass : idleClass`.
- Tailwind 클래스를 추가할 때 클래스가 만드는 효과를 직접 확인한다. `gap-2`는 요소 사이 간격, `px-4`는 좌우 안쪽 여백처럼 기본 단위를 하나씩 익힌다.
- Tailwind v4에서는 기본적으로 별도의 `tailwind.config.js`를 만들지 않는다. 공통 색상·간격 토큰이 필요해질 때 CSS 변수와 공통 컴포넌트 도입을 먼저 검토한다.

## 6. 유지보수하기 쉬운 코드 기준

코드는 레고 블록처럼 작고 역할이 분명해야 한다. 한 블록이 화면 표시, IPC 통신, 상태 변경을 모두 담당하면 나중에 고치기 어렵다.

- 하나의 함수와 컴포넌트는 하나의 주요 책임만 가진다.
- Renderer 화면, Preload API, Electron Main 로직의 책임을 섞지 않는다.
- 이벤트 핸들러 이름은 동작이 보이게 짓는다. `handleStudyStart`, `handlePermissionChange`처럼 작성한다.
- 긴 조건문은 의미 있는 함수 또는 상수로 분리한다.
- 같은 문자열과 숫자를 여러 번 쓰지 말고 상수로 관리한다.
- 페이지 컴포넌트에 복잡한 로직을 몰아넣지 않는다.
- macOS 권한·화면 캡처·카메라 관련 동작은 호출 전제조건과 중지 조건을 주석으로 남긴다.
- 앱 종료·재실행·네트워크 끊김에서도 상태가 어떻게 되는지 정한다.
- 주석과 문서가 코드와 달라지면 즉시 고친다. 오래된 주석은 없는 것보다 더 위험하다.
- 변경 범위를 작게 유지하고, 한 번에 한 가지 목적만 수정한다.

## 8. 학습 기록 예시

```md
### 이번 작업에서 배운 것

- `useState`: 사용자의 클릭으로 바뀌는 값을 저장하는 React Hook.
- `'use client'`: 브라우저 이벤트와 상태를 사용하는 파일임을 Next.js에 알리는 지시문.
- 유니온 타입: 세션 상태처럼 가능한 값을 제한해 오타를 컴파일 단계에서 찾는 TypeScript 문법.

### 유지보수 메모

- 권한 요청은 Renderer가 직접 처리하지 않고 Preload가 노출한 API를 통해 호출한다.
- 세션 상태 타입은 API와 화면에서 함께 사용하므로 `packages/shared-types`에서 관리한다.
```
