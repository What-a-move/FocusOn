# 할 일 적기 질문 재시도 오류

## 증상

질문에서 문장을 수정한 뒤 다시 확인하면 400이 발생할 수 있었다. 질문 답변 요청이 실패하면 초기 입력으로 돌아가고, 답을 그대로 다시 제출하기 어려웠다.

## 확인한 원인

- 서버는 대화 단계 번호와 답변 수가 같아야 하고, 이미 시작한 대화에는 그 대화에서 받은 질문과 같은 문장의 답을 받아야 한다. 수정한 문장에 이전 대화 ID가 남으면 새 요청이 이전 대화의 응답으로 해석된다.
- 최초 AI 확인에 대한 별도 사용자 재현은 Backend가 `503 GOAL_ANALYSIS_UNAVAILABLE`을 반환한 경우였다. Desktop과 Backend에서 동일 요청을 확인했다(`36b4b176-e989-43a4-9433-b072f01c53a3`). 이후 같은 환경의 합성 입력으로 호출한 내부 AI 경로는 200을 반환했다. 당시 503의 내부 원인은 확인되지 않았다.

## 수정 및 검증

- 문장 수정은 대화 ID와 답을 초기화한다. 질문 표시 횟수 제한은 유지한다.
- 요청의 대화 단계는 전송한 답 개수로 계산한다. 질문 중 오류가 나면 화면과 답을 유지하고 같은 답을 다시 제출할 수 있다.
- 직접 저장은 실패하거나 오래된 AI 대화에 의존하지 않는다. 첫 확인에 실패했을 때는 다시 시도와 직접 저장 버튼을 분명히 구분한다.
- Desktop 빌드 및 모의 IPC 브라우저에서 문장 수정, 단계 번호, 실패 후 동일 답 재전송, 직접 저장, 초기 실패 안내를 확인했다. 실제 앱·AI 조합의 질문 흐름은 별도 확인이 필요하다.

## AI 확인 성공 후 저장 오류

Desktop에서 명확화 `200` 직후 목표 생성 `400 VALIDATION_ERROR`를 확인했다. 생성 요청 추적 ID는 `cb4d86ab-3ab3-4cfb-8216-28d646b1e9d8`이다. 회귀 재현에서 첫 확인 직후 자동 저장으로 넘어갈 때 React 상태 갱신 전 값으로 요청을 구성해 필수 대화 ID가 빠지는 것을 확인했다. 저장 입력에 방금 받은 대화 ID를 직접 전달하고, 백엔드는 이 ID로 검증된 초안을 찾는다. 새 할 일 화면은 범위를 편집하지 않으므로 초안을 생성 요청에서 다시 보내지 않는다.
