## 기능 목적

- 카메라 분석(#222)은 있지만 설정에 스위치가 없어 사용자가 켤 수 없었다(결정 029에서 구현 때 넣기로 함).
- 카메라가 동작하지 못한 이유를 사용자가 볼 곳이 없었다.

## Desktop 상세 동작

- 설정 › 분석·권한 탭, 필수 권한 아래에 `카메라 분석 [선택]` 행과 스위치.
- 켜기: macOS 카메라 권한 확인(처음이면 OS 허용 창, 거부했으면 다시 묻지 않음) → 카메라 동의(CAMERA_ANALYSIS)가 없으면 서버 현재 버전으로 저장 → focus-settings `cameraAnalysisEnabled: true`. 서버는 카메라를 켠 세션 시작 때 동의를 확인한다.
- 끄기: focus-settings를 끈 뒤 카메라 동의도 철회한다(계정 탭에 카메라 철회가 없어 스위치가 맡는다, CodeRabbit 리뷰 반영).
- 오류는 macOS가 확실히 알려 주는 두 가지만 한 줄로 보여 준다(사용자 결정).
  - 권한 꺼짐(켜 둔 경우): `카메라 권한이 꺼져 있어요` + `시스템 설정 열기`(카메라 권한 화면)
  - 카메라 없음(집중 중 도우미가 기본 카메라 자체를 못 찾음): `카메라를 찾을 수 없어요` + `다시 시도`(사유 지우기). 장치는 있는데 준비만 실패하면 사유 없이 넘긴다.
- 설정을 읽지 못하면 기본값을 넣지 않고 `설정을 불러오지 못했어요` + `다시 시도`. 창 복귀 조회가 스위치 저장보다 늦게 끝나도 덮지 않는다.
  - 시안의 `다른 앱이 사용 중`은 프레임이 안 오는 것으로 추정할 수밖에 없어 넣지 않는다.
- Main: 도우미가 거부·장치 없음 사유를 `ok`로 돌려주고, `CameraMonitor`가 마지막 사유를 세션이 끝나도 남겨 둔다. 정상 프레임이나 다시 시도로 지운다.
