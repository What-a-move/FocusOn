## 기능 목적과 단계

세션 중 페이지마다 노트를 만들지 않고 종료 후 정리 하나를 보여준다. 첫 단계는 가짜 세션 데이터로 화면·상태·복사를 직접 확인하는 **개발 시연**이고 제품 연동이 아니다. 다음 단계에서 Server 종료·시간 확정과 `GET /api/v1/sessions/{sessionId}/learning-summary`를 연결한다.

## 사용자 흐름

1. 개발 시연 화면에서 합성 세션을 종료한다.
2. `QUEUED`/`GENERATING` 진행 안내를 본다.
3. `READY`이면 개요·핵심 개념·다음 시작 지점을 보고 복사한다. `INSUFFICIENT_DATA`/`FAILED`이면 각각 다른 안내를 본다.

## Desktop 상세 동작

- 진입 조건: 데모는 개발 환경에서만 접근 가능하며 항상 `데모 데이터`로 표기한다. 실제 제품은 서버가 `ENDED`와 시간을 확정한 세션의 조회 화면에서만 진입한다.
- 정상 동작: 시연 Fixture는 컴포넌트 밖에 두고 실제 API 데이터와 혼합하지 않는다. 제품 연결 시 pending 상태를 5초마다 조회하고 terminal 상태에서 중단한다.
- 종료 조건: 화면 이동·세션 변경 시 진행 타이머 또는 조회를 중단한다. 이미 보여준 `READY`는 늦은 응답으로 덮지 않는다.
- 상태 변화: 제품 세션 `ENDING → ENDED`, 정리 `QUEUED → GENERATING → READY / INSUFFICIENT_DATA / FAILED`.

## macOS 권한 및 시스템 기능

- 시연에 화면 기록·카메라·알림·활성 앱 확인 권한은 필요 없다. Electron IPC와 OS 화면 캡처도 사용하지 않는다.
- 실제 근거 수집은 이 화면이 하지 않으며 #11 및 Client 개인정보·제외 계약이 선행된다.

## 화면 및 사용자 경험

- 화면 위치: 개발 전용 학습 정리 시연 Route. 실제 조회 위치는 세션 리포트와 연결할 때 확정한다.
- 주요 컴포넌트: 시연 시나리오 선택, 종료 버튼, 진행 상태, 결과 카드, 복사 버튼, 근거 부족·실패 카드.
- 로딩·빈 상태·오류: 각 상태를 텍스트와 색상으로 함께 구분하며, 실패를 빈 결과로 표시하지 않는다.
- 접근성: 버튼 키보드 조작, 상태 영역 `aria-live`, Focus 표시, 복사 성공·실패 안내를 확인한다.

## 데이터 및 IPC/API

- 시연 Renderer 입력: 개인 데이터가 아닌 고정 합성 Fixture. 실제 API·AI 호출 없음.
- 제품 조회 계약: `GET /api/v1/sessions/{sessionId}/learning-summary`; 인증·소유권은 Server 책임.
- 저장: 시연은 영구 저장하지 않는다. 실제 정리·근거 보존은 Server와 루트 `docs/DATA_PRIVACY.md` 계약을 따른다.
- 원본 DOM·OCR·URL·이미지는 Desktop 정리 화면에 전달하지 않는다.

## 예외·개인정보

| 상황 | 시연/제품 화면 처리 |
| --- | --- |
| 근거 0·1개, 중복만 있음 | `INSUFFICIENT_DATA`; 근거를 꾸며내지 않음 |
| 모델·통신 실패 | `FAILED`; 세션 종료·시간 기록은 유지 |
| 제외·민감 화면·동의 철회 | 정리 근거로 사용하지 않음; 제품 통합 테스트 전 미연동 |
| 권한 거부 | 시연은 영향 없음; 실제 분석 연결 시 정리와 별도 처리 |

- 카메라·화면 원본 저장: 없음.
- 시연 데이터 메모리 유지: 화면이 열려 있는 동안만.
- 제품 데이터 외부 전송: 팀의 제공자·보존·사용자 고지 승인 전 비활성화.
