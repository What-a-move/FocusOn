# 포키 창 로드 실패에 성공한 전송 기록을 보냄

- 2026-11-19 · Desktop · [#286](https://github.com/What-a-move/FocusOn/issues/286)
- 발견 경로는 [#285 리뷰](https://github.com/What-a-move/FocusOn/pull/285)다.

## 재현과 기대 결과

보통 팝업을 준비하는 동안 포키 페이지 로드를 실패시키거나 창을 닫는다. 성공으로 기록하면 화면에는 첫 알림이 없었는데 다음 알림부터 2차로 올라갈 수 있다. MOLE_UI만 사용하면 `NOT_SENT`를 보내고 다음 보통은 같은 단계여야 한다.

## 추정 원인

리뷰에서는 로드 완료와 무관하게 호출 순간에 성공을 처리한다고 봤다.

## 실제 원인

Main의 watcher 어댑터는 `showFloating`을 호출한 직후 `true`를 반환했다. 창의 `loadURL`은 비동기로 끝나므로 watcher가 MOLE_UI를 SENT로 표시하고 연속 횟수를 올린 뒤에도 창 로드 실패가 발생할 수 있었다.

## 수정 및 검증

Main은 로드를 마치고 현재 요청의 창이 보이는지까지 확인해 결과를 반환한다. 로딩 중 회차·전경이 바뀌거나 알림의 남은 시간이 지나면 전송을 중단한다. watcher는 결과를 기다려 실제 성공 채널과 보통 단계를 확정한다.

회귀 테스트에서 지연된 창 실패가 NOT_SENT이며 다음 보통이 1차로 나오는 것을 확인했다. 로딩 도중 시간 만료 시 macOS 알림도 전송하지 않는지 검증했다. Desktop 테스트 194개와 Electron 타입 컴파일, 변경 파일 ESLint가 통과했다. 실제 서버의 포키 표시 검증은 통합 QA에서 진행한다.

## 리뷰 후속

로드 응답을 받지 못하면 4초 뒤 해당 창을 정리하고 NOT_SENT로 완료한다. 창을 띄우기 직전에 보통 단계의 만료를 다시 계산한다. 로딩 중 10분을 넘으면 1차 창을 사용하고 다음 보통은 2차로 이어지는 것을 테스트했다. 최종 Desktop 테스트 195개를 통과했다.
