# 포키 흐림 오버레이가 작업 영역에 갇힘

- 기능: 강도별 포키 딴짓 알림
- 관련 이슈: [#282](https://github.com/What-a-move/FocusOn/issues/282)
- 발생 일시: 2026-11-19
- 대상: 노치가 있는 Apple Silicon 내장 주 화면(1512×982pt), Electron 44.1.0
- 상태: 해결

## 재현과 실제 결과

노치 Mac에서 별도 전체 화면 Electron 앱 위에 투명 패널을 띄우고, `showInactive()` 직후 주 화면의 전체 좌표를 다시 지정했다. 요청은 `(0, 0, 1512, 982)`였지만 실제 창은 `(0, 33, 1512, 879)`로, 화면 위 33pt와 아래 70pt가 비었다.

## 원인 및 해결

- 추정 원인: 기존 작은 포키 창처럼 최초 표시 순간에만 macOS가 위치를 보정하는 것으로 봤다.
- 실제 원인: 전체 화면 크기의 일반 투명 패널을 제약 없이 만들지 않으면 표시 후 다시 준 좌표와 크기도 작업 영역으로 제한됐다.
- 해결: 큰 오버레이에 `enableLargerThanScreen: true`, `roundedCorners: false`를 지정하고 기존 `showInactive() → setBounds()` 순서를 유지했다. 작은 포키 창은 기존 배치와 Dock 보정을 사용한다.

## 확인 결과

주 모니터 전체 좌표와 오버레이 실측이 일치했다. 전체 화면 앱의 실측은 `(0, 33, 1512, 949)`였고, 오버레이는 노치 줄과 Dock 높이에 해당하는 영역까지 덮었다.
