# 설치형 앱에서 집중 화면을 열 때 내부 페이지 요청 실패 (#283)

## 재현과 영향

설치형 앱에서 목표를 수동 확정하고 5분 세션을 시작했다. 시작 응답(201)과 heartbeat(200) 뒤 창에 타이머와 조작 버튼이 보이지 않았다. 재실행하면 홈은 진행 중인 세션을 복구했지만 ‘집중 화면으로’에서 같은 증상이 나타났다. 학습 노트 → 집중 기록에서도 빈 창을 관측했다.

## 추정 원인

처음에는 세션 시작 또는 복구 실패를 의심했다. 서버 요청과 Main의 상태 전이에서 RUNNING과 목표 도달을 확인했다. 세션 시작 traceId는 `841c6b3d-9cdf-49ba-97fb-1a8bd13bbbe9`, 재실행 후 활성 조회는 `2a3a7ec1-0117-4b4b-bd37-30005668b343`이다.

## 실제 원인과 검증 범위

설치본 로그에서 Next.js의 `app://focuson/session/index.txt` 요청이 ‘URL scheme "app" is not supported’로 실패한 후 문서 전체를 다시 여는 동작을 확인했다. Electron의 앱 프로토콜에 Fetch API 지원을 등록하지 않아 발생한 요청 실패다. [Electron 프로토콜 문서](https://www.electronjs.org/docs/latest/api/protocol/)

설치본의 실제 정적 파일과 같은 Electron 버전으로 세션 설정의 ‘집중 시작하기’를 눌렀다. 서버와 계정이 필요 없는 비교를 위해 이 시험에서만 세션 시작·현재 상태를 고정했다.

| 항목 | 수정 전 | 수정 후 |
| --- | --- | --- |
| 세션 페이지 데이터 요청 | TypeError | 200, 3,843바이트 |
| 시작 버튼 뒤 문서 전체 재탐색 | 1회 | 0회 |
| 시험 창의 최종 타이머 | 표시 | 표시 |

시험에서 수정 전에도 전체 재탐색 후 타이머가 나타났다. 이 비교로 재현한 범위는 페이지 요청 실패와 재탐색이다. 설치형 빈 화면이 지속되는 조건은 별도로 확인한다.

## 수정

Main의 기존 `app` 스킴 등록에 `supportFetchAPI: true`를 추가했다. 기존 출처·경로 검증과 GET·HEAD 제한을 적용한다. Electron 컴파일과 Desktop 테스트 186개가 통과했다.

별도 경로에 수정본을 패키징하고 기존 사용자·서버 설정으로 홈 → 11월 19일 기록 → 회차 리포트 → 홈 → 목표 → 세션 설정까지 이동했다. 주간 기록과 리포트가 화면에 정상 표시됐다.
