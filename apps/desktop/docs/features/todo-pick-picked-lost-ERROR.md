## 오류 제목

- 새 할 일을 저장하면 "할 일에 담았어요"가 뜨는데, 할 일 고르기에서는 골라져 있지 않고 카드를 눌러도 선택되지 않음

## 실행 환경

- Electron 44.1.0, Next dev 서버(127.0.0.1:3000), 로컬 서버(docker compose)
- 앱은 13:50에 켠 뒤 그대로였고, 그 사이 브랜치를 여러 번 바꿔 Fast Refresh로만 화면 코드가 갱신됨

## 재현 방법 (사용자 보고)

1. 할 일 고르기 빈 화면 → `할 일 적기`
2. `미적분 적분 문제 풀기` 입력 → AI 확인 실패(503 `GOAL_ANALYSIS_UNAVAILABLE`) → `입력한 그대로 시작` → `이 목표로 정하기`
3. 완료 화면 "이번 집중 목표 / 할 일에 담았어요" → `할 일 고르기`
4. 같은 과정을 한 번 더 → 같은 글의 할 일이 2개(id 18·19) 생김
5. 할 일 고르기에서 두 카드 모두 안 골라져 있고, 눌러도 선택되지 않음

## 기대 결과

- 저장한 할 일이 골라진 채로 보이고, 카드를 누르면 선택된다.

## 실제 결과

- 골라져 있지 않고 선택도 되지 않음(사용자 화면).

## 원인 및 해결

- 추정 원인: 오래 켜 둔 개발 앱에서 브랜치를 바꾸며 Fast Refresh가 쌓여 화면 상태가 꼬였을 가능성. 확인하지는 못했다.
- 확인한 것: 앱을 다시 켠 뒤 같은 DB 데이터(id 18·19)로
  - 저장소에 고른 할 일이 있을 때 /todo/에서 골라져 보임
  - 실제 마우스 클릭(CDP `Input.dispatchMouseEvent`)으로 두 카드 모두 선택됨
  - 카드 위를 덮는 요소 없음(`elementFromPoint`)
  - 모두 정상이라 재현되지 않았다.
- 함께 고친 것(실제 문제):
  - 새 할 일 적기가 예전 "이번 집중 목표" 흐름 그대로였다. 문구(`오늘은 무엇에 집중할까요?`, `이번에 끝낼 일 하나`, `이번 집중 목표`)가 할 일 적기와 맞지 않았다.
  - 할 일 하나도 확인 화면과 완료 화면을 거쳤다.
  - 같은 글의 할 일도 새로 만들었다.
  - 수정: 시안(`todo-goals.html?view=add`)대로 `어떤 할 일을 적을까요?`·`저장`·`입력한 그대로 저장`으로 바꿨다. 할 일 하나는 바로 저장하고 할 일 고르기로 돌아가 골라 두고 한 줄 안내를 띄운다. 같은 글이 있으면 새로 만들지 않고 그 할 일을 골라 둔다. 나눈 할 일만 확인 화면을 거친다.
- 변경 파일: `features/goal/GoalSetting.tsx`, `features/goal/goal.css`, `features/goal/TodoPick.tsx`, `features/goal/todo-pick.css`, `shared/api/goal-api.ts`

## 확인 결과

- 실제 앱(CDP): 같은 글 입력 → 새로 만들지 않고 /todo/에서 골라짐 + `같은 할 일 ‘…’이(가) 이미 있어서 그걸 골라 뒀어요.`
- 브라우저 가짜 응답: AI 실패 → `입력한 그대로 저장` → 저장 후 골라짐, AI CLEAR → 확인 없이 저장 후 골라짐
- 다시 생기면 앱을 `--remote-debugging-port`로 켜 두고 그 상태에서 `aria-checked`·`sessionStorage`를 바로 확인한다.
