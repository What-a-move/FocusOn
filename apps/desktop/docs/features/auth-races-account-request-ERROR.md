## 오류 제목

- 계정 전환 뒤 이전 계정 요청이 새 계정 토큰으로 다시 보내지거나 새 계정 화면에 반영됨

## 실행 환경

- macOS 버전: Darwin 25.6.0 (Apple Silicon)
- Electron 버전: 44.1.0 (Main `AuthService`를 `node --test`로 실행, 실제 앱 UI는 미확인)
- Node.js·pnpm: Node 24.14.1
- 화면 기록 권한: 해당 없음
- 카메라 권한: 해당 없음
- 재현 방식: 지연시킨 가짜 API·Keychain(vault)과 실제 `AuthSessionStore`. 토큰·인증 코드 원문은 기록하지 않는다.

## 재현 방법

1. A 계정으로 PUT 요청을 보내고 응답을 지연시킨다.
2. 로그아웃 후 B 계정으로 로그인한다.
3. A 요청에 만료(`AUTH_ACCESS_TOKEN_EXPIRED`) 또는 성공 응답을 돌려준다.

## 기대 결과

- A 요청은 실패로 끝나고 B 토큰으로 다시 보내지지 않는다. B 화면은 바뀌지 않는다.

## 실제 결과

- A의 요청 body가 B 토큰으로 1회 재전송된다. 늦은 성공 응답도 B 화면(닉네임 등)에 반영될 수 있다. GET 재시도 대기 중 계정이 바뀌어도 추가 요청이 나간다.

## 오류 메시지

```text
화면 오류 메시지 없음. `tests/electron/auth-races.test.cjs` 27개 중 수정 전 20개 실패·7개 통과 → 수정 후 27개 통과.
```

## 원인 및 해결

- 추정 원인: 재전송 때 토큰만 새로 읽어서 생기는 문제라고 봤다.
- 실제 원인: 요청을 시작할 때의 로그인 세대를 기록하지 않아, 재전송·재시도·결과 반영 직전에 "지금도 같은 로그인인가"를 확인할 방법이 없었다.
- 공통 원인: "요청을 시작할 때의 로그인 = 지금 로그인인가?"를 Google 로그인 교환에서만 확인했다.
- 해결 방법: 요청 시작 때 세대를 기록하고 전송 전·응답 후·재시도 대기 뒤마다 확인한다. 세대가 바뀌면 `AUTH_RELOGIN_REQUIRED` 실패로 돌려주되 새 계정의 토큰·화면은 건드리지 않는다.
- 변경 파일: `electron/main/auth-service.cts`, `electron/main/auth-ipc.cts`, `tests/electron/auth-races.test.cjs`
