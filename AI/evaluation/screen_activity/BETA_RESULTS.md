# 4,743건 화면 활동 모델 베타 평가

## 평가 기준

모델은 화면을 공부 중(`STUDY`), 딴짓(`OFF_TASK`), 판단 보류(`UNCERTAIN`)로 분류한다. 학습 목표 문구는 모델 입력에서 제외한다. 학습 4,743건의 라벨은 공부 1,527건, 딴짓 1,423건, 보류 1,793건이다. 입력별로는 탭 메타데이터 1,405건, Chrome DOM 1,349건, 앱 메타데이터 1,020건, 데스크톱 OCR 969건이다.

상위 두 점수 차이 기준은 1%p다. Chrome은 활성 탭 메타데이터부터 보고 필요할 때 DOM을 요청한다. 데스크톱은 앱 메타데이터에서 시작해 필요할 때 OCR을 요청한다. 개인정보 보호 검사를 통과한 네이티브 VS Code는 앱 정책으로 공부 처리한다. 웹 평가에는 당시 로컬 HTTP 데모의 단계별 응답을 사용했다. 메타데이터에서 나온 딴짓은 본문 확인으로 넘기고, 점수가 0.60 미만인 확정 판정도 보류했다. 이번 PR의 팀원 실행 경로에서 새 Chrome 화면 22개의 첫 판정·DOM 요청 여부·최종 판정을 재생해 기존 기록과 22/22가 일치했다.

## 새 실제 Chrome 화면 22개

공개 페이지 22개를 수집해 예측 전에 정답을 정했다. 알려진 기존 자료와 URL, 정규화한 제목 또는 DOM 본문 전체가 일치하는 화면은 제외했다. 22개 중 한 도메인은 과거 평가와 겹친다. 일상 사용 빈도를 반영한 무작위 표본은 아니다.

- **최종 19/22(86.4%)**. 공부 6/6, 딴짓 5/6, 보류 8/10. 같은 입력에서 3,944건 모델은 20/22, 직전 4,648건 모델은 18/22였다.
- 같은 **최종 정답**과 비교하면 탭 메타데이터만으로는 12/22였고, 18개 화면에서 DOM을 추가로 읽은 뒤 19/22였다. [공개 페이지별 첫 판정과 최종 판정](data/beta-chrome22-results.json)에서 어느 화면의 결과가 바뀌었는지 볼 수 있다. 메타데이터만 보고 보류해야 하는 경우까지 반영한 **첫 단계 전용 정답**과는 16/22가 일치했다.
- Dailymotion의 오락 추천 피드(딴짓)는 DOM까지 읽고도 보류 점수가 71.55%였다. 빈 DrawIsland 그림 도구(보류)는 DOM의 게시 안내를 읽은 후 딴짓 점수가 85.81%였다.
- HackMD 기능 소개(보류)는 탭 제목만으로 공부 점수 95.50%가 나와 DOM 요청 전에 종료됐다. 진단을 위해 같은 DOM을 따로 넣으면 보류 점수 68.89%였다. 이 점수는 보정하지 않은 모델 출력이다.

## 기존 평가와 취약한 화면

- 현재 라벨 정책으로 각 입력을 분류기에 직접 넣은 **기존 고정 데이터**는 600건 중 571건(95.2%), 별도 240건 중 229건(95.4%)을 맞혔다. 같은 기준의 3,944건 모델은 각각 545/600, 209/240이었다. 4,743건 모델에서 공부·보류를 딴짓으로 판정한 입력은 각각 12건과 8건이었다. 이 중 600건은 학습 가중치 설정을 선택할 때도 사용한 개발 세트다.
- 기존 웹·데스크톱 고정 화면 세 묶음의 로컬 HTTP 최종 판정은 각각 25/28, 26/29, 26/29였다. 28개 묶음의 분모에는 본문이 차단되어 판정하지 못한 한 화면이 포함된다. 기존 YouTube 화면은 30/33이었다. 이 YouTube 묶음도 후보 설정을 고르는 데 사용했다.
- **캔버스 화면은 8/19(42.1%)**였다. 공부 7건 중 1건, 딴짓 5건 중 1건, 보류 7건 중 6건을 맞혔다. 화면 안의 실제 작업·플레이를 DOM 텍스트만으로 구분하는 데 오차가 크다.

## 무알림 세션 재생

- **4시간 모의 세션**에서 실제 수집 화면을 정해 둔 순서와 시간으로 재생했다. 딴짓 구간 15개 중 정답 상태를 사용해도 알림 조건을 충족하는 구간은 7개였고, 모델 응답으로는 5개에서 후보가 생겼다(71.4%). 공부로 정한 10,880초(3시간 1분 20초) 동안 오알림 후보는 0회였다. 근거 수집이 차단된 요청도 있었다.
- **Next.js 문법 1시간 모의 세션**은 문서 읽기 22분과 VS Code 실습 38분으로 설정했다. 문서 구간 5개 모두 DOM을 읽은 후 공부, VS Code 구간 5개 모두 앱 정책으로 공부가 되어 10/10, 오알림 후보 0회였다. 딴짓 구간은 없었다.
- **트랜스포머 1시간 모의 세션**에서는 분석 가능 구간 15/15의 최종 판정이 맞았다. 나머지 1구간은 개인정보 보호로 분석을 생략했다.
- 모의 세션에서 실제 알림은 발송하지 않았다. 팀원 베타 대시보드는 사람이 확인한 공부 시간당 오알림 후보와 관찰 가능 시간 비율을 표시한다. 지속 딴짓 누락을 평가하려면 후보가 없었던 시간까지 사람이 활동 구간을 표시한 뒤 알림 조건과 대조해야 한다.

## 로컬 API 응답 시간

한 대의 Mac에서 준비가 끝난 단일 워커에 네 종류의 짧은 입력을 반복해 보냈다. 동시 요청 1·4·8개에서 각각 80/80건이 HTTP 200을 반환했다. 중앙값은 각각 9.1·27.0·54.1ms, p95는 14.4·29.8·58.4ms였다. 가장 높은 서버 프로세스 RSS 표본은 819.8MiB였다. 캡처·OCR 처리 시간과 전체 데스크톱 앱 메모리는 이 측정 범위 밖이다.

팀원 베타에서 측정할 실행 비용은 전면 창 확인과 OCR에 쓰이는 시간·CPU다. 현재 관찰 루프는 세션 진행 중 약 1.5초 간격으로 전면 창을 조회하며, 해당 비용은 위 API 부하 측정에 포함되지 않는다.

베타에서는 실제 공부 시간당 오알림과 지속 딴짓 누락을 우선 확인한다. 특히 빈 도구를 딴짓으로 확정하는 경우와 제목만으로 공부를 확정해 DOM을 건너뛰는 경우를 구분해 기록한다.
