# 할 일 매칭 기술 계열 평가 · 2026-11-25

초기 오프라인 실험에서는 기술 계열 일치로 다른 기술을 잘 구분했지만 세부 할 일까지 귀속하면 잘못된 매칭이 늘었다. 후속 구현과 결과는 이 문서의 마지막 절에 기록했다.

## 평가 방법

원본 results.csv의 new(기존 Backend·AI 실측)를 기준선으로 삼았다. 새 방식은 동일한 저장 DOM·Apple Vision OCR 및 메타데이터를 로컬 E5에 재입력했다. Backend HTTP 왕복과 신규 화면 캡처는 측정 범위 밖이다. E5 활동 판정이 STUDY일 때만 매칭한다. 메타데이터에서 매칭을 확정하지 못하면 본문으로 재판정하므로 활동 판정까지 도달한 분모가 달라질 수 있다.

01~05의 화면 156개, 화면×세션 671행으로 상위 주제 수, 득표율, 기술명 보너스, 탭 제목 매칭 허용 여부 36개 조합을 비교했다. 같은 기술 매칭률과 다른 기술 FAR율을 각각 세트별로 평균한 후 두 값에 같은 비중을 줬다. 다른 기술 사례는 튜닝 세트 중 01에만 있다. 세부 할 일 정확도는 튜닝 목적함수에 포함하지 않았다.

고정 커밋 bc3255d. 분야 96개에서 일부 동의·하위 분야를 묶고, 화면 제목·본문 조각과 할 일 문장·대표 주제·핵심 주제 각각을 2,782개 E5 주제와 비교했다. 상위 3개 주제의 계열 득표와 명시적 기술명 보너스 0.75를 결합했다. 1위 비중 35% 이상, 1·2위 점수 차 0.10 이상이면 계열을 채택한다. 같은 계열이면 선택된 할 일 중 유사도가 가장 높은 하나를 반환한다. 다른 계열은 본문에서만 FAR를 허용한다. 미확정 계열이나 일부 인접 계열은 보류한다. 계열 경계는 이 실험의 가정이다.

## 채점 전용 06·07 해석

화면 65개를 여러 세션에 재사용해 975행을 채점했다. 실제로 공부로 판정한 경우, 다른 기술 FAR는 51/660 → 636/660, 다른 기술 오매칭은 1/660 → 0/660, 다른 기술 보류는 608/660 → 24/660이었다. 같은 기술 매칭은 94/171 → 168/177, 같은 기술을 FAR로 보낸 건 0/171 → 6/177이었다. 두 방식 모두 공부로 판정한 동일 행에서만 비교해도 같은 기술 매칭은 92/169 → 160/169였다.

세부 할 일 정답은 116/159 → 65/164였다. 정답 할 일을 직접 맞힌 건 57 → 62건, 정답 할 일이 없어 올바르게 거절한 건 59 → 3건, 엉뚱한 할 일을 고른 건 31 → 93건이다. 기술이 같다는 이유로 화면마다 선택된 할 일 하나에 귀속시키는 정책에서 발생한 차이다. K8s 배포 메모와 Express 라우팅 가이드는 같은 기술인데도 각각 세 세션에서 FAR가 나왔다.

원자료에서 01의 Vue props와 07의 Vue props 문서 본문(공백 정규화 후 2,000자)이 같았다. 확정 목표 문장은 두 분할 간 정확히 겹치는 것이 없었다. 이 화면을 뺀 보조 집계에서도 다른 기술 FAR는 51/648 → 624/648, 같은 기술 매칭은 92/168 → 165/174였다. 06·07 결과를 본 후 기준을 수정하지 않았다. 세부 라벨은 사람 검수 전이므로 개별 오판 확정에는 수기 확인이 필요하다.

## 재현

저장소 루트에서 E5와 프로젝트 의존성이 설치된 Python을 사용한다. DATA는 원본 README.md·cases.csv·results.csv·sets/가 있는 폴더, MODEL은 설치된 E5 모델 디렉터리, OUT은 새 결과 디렉터리다.

```sh
export PYTHONPATH=AI:. HF_HUB_OFFLINE=1
python AI/evaluation/tech_family/evaluate.py tune --data "$DATA" --model "$MODEL" --out "$OUT"
python AI/evaluation/tech_family/evaluate.py grade --data "$DATA" --model "$MODEL" --out "$OUT"
```

고정값만 재현하려면 OUT에 동봉한 frozen.json을 복사하고 grade를 실행한다. 원본 저장 시 사용한 명칭인 new가 기존 결과이고 family_* 열이 실험 결과다. grade.csv에서 각 화면과 세션의 판정을 확인할 수 있다. 실행 시 로컬 토크나이저 정규식에 관한 라이브러리 경고가 있었다. dev 기준의 토크나이저 설정 그대로 채점했다.

## 세부 할 일 매칭과 기술 계열 FAR 결합

기존 실측의 세부 할 일 매칭과 수집 순서를 기준으로 재현했다. 본문까지 받고 RELATED + NOT_ENOUGH인 행에만 고정 계열 분류기와 E5 본문 단독 STUDY 판정을 적용했다. 두 조건을 충족하면 FAR로 바꿨다. 평가 규칙은 7f831e3에 고정했다. 06·07은 앞선 계열 실험에서 이미 채점한 화면이며 이번 확인에서도 임계값 조정에는 사용하지 않았다.

- 06 · 다른 기술 FAR 29/324 (9.0%)에서 265/324 (81.8%)로 증가했다. 같은 기술의 잘못된 FAR는 0/83이었다.
- 07 · 다른 기술 FAR 22/336 (6.5%)에서 335/336 (99.7%)로 증가했다. 같은 기술의 잘못된 FAR 6/88 (6.8%)가 나왔다. Express 라우팅 가이드와 Express 미들웨어 문서가 각 세 세션에서 잘못 바뀌었다.
- 합산 · 다른 기술 FAR 51/660 (7.7%)에서 600/660 (90.9%)로 증가했다. 세부 할 일 정답은 양쪽 모두 116/159 (73.0%), 엉뚱한 세부 할 일 매칭은 각각 31건이었다. 같은 기술 매칭은 94/171 (55.0%)이었다. 01과 겹치는 Vue 문서를 빼도 다른 기술 FAR는 51/648 (7.9%)에서 588/648 (90.7%)로 증가했다.

65개 저장 화면의 세션 조합 975행을 평가했다. 기존 결과와 결합 결과의 화면 활동 판정과 매칭된 할 일 ID가 전 행에서 일치한다. 이 실행은 저장 API 결과에 로컬 E5 보조 판정을 결합한 재현이다. 제품 반영과 실시간 API 지연 측정은 후속 확인에 해당한다.

```sh
export PYTHONPATH=AI:. HF_HUB_OFFLINE=1
python -m AI.evaluation.tech_family.evaluate_far_fallback --data "$DATA" --model "$MODEL" --out "$OUT"
```

## 본문 근거 매칭과 기술 계열 FAR 구현 비교

2번 적용 커밋 853e1fd와 1·2번 적용 커밋 6313e3d를 같은 저장 DOM·OCR 화면 65개와 975개 세션 조합으로 비교했다. 최신 dev bd55c8f 기반의 실제 FastAPI와 로컬 E5를 실행했다. 규칙을 01~05에서 검토한 뒤 고정했다. 06·07은 이전 실험에서 채점에 사용된 표본이며 이번에도 기준 조정에는 사용하지 않았다. 세부 라벨은 실험 자료의 라벨이다.

- 두 버전 모두 RELATED이며 선택 할 일의 정답이 모두 명확한 같은 기술 151개에서, 세부 할 일 정확도는 115/151 (76.2%)에서 127/151 (84.1%)로 올랐다. 정답 할 일이 있는 화면의 올바른 매칭은 56건에서 53건, 다른 할 일에 붙인 건 24건에서 9건, 매칭 누락은 12건에서 15건이었다. 정답 할 일이 없는 화면을 제대로 비워 둔 건 59건에서 74건이다.
- 다른 기술 FAR는 593/660 (89.8%)에서 594/660 (90.0%)였다. Vue 반응형 문서가 Node.js fs에 붙던 한 건이 FAR로 바뀌었다. 같은 기술 FAR는 0건에서 1건으로 늘었다. Kubernetes 배포 메모에서 Service 할 일만 선택한 조합이었다.
- Express를 선택한 네 조합은 모두 Express에 붙었다. Node.js fs만 선택한 두 조합은 NOT_ENOUGH였다. MongoDB OCR 집계 메모는 제품명 없이 집계 연산자가 반복되는 코드에서 근거를 얻어 aggregation에 붙었다. Rust 스레드는 NOT_ENOUGH로 바뀌었다. Kubernetes PV/PVC 문서는 아직 Service에 붙고, S3 업로드 화면은 DOM 활동 분류에서 UNCERTAIN이었다.
- 본문 요청이 943회에서 975회로 늘었다. 같은 기술 화면 6개 조합은 TAB_META에서 종료되던 흐름이 DOM까지 이어지면서 최종 RELATED가 UNCERTAIN으로 바뀌었다. 활동 모델과 임계값은 동일했다. 12개 진단용 합성 표본 재실행은 9/12에서 11/12였다.
- AI 테스트 450개, 하위 테스트 27개 통과. 대량 재현에서는 같은 모델 계산을 평가 러너 안에서 재사용했다. 실시간 왕복 지연은 측정하지 않았다.
