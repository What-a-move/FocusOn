# 목표·세션·회차 모델 명세

## 문서 상태

- 상태: 팀 검토용 계약 초안, 미구현
- 버전: `0.1.0`
- 기준일: 2026-09-12
- 관련 Issue: [#3](https://github.com/What-a-move/FocusOn/issues/3)
- 관련 규칙: `AI-GOAL-001`, `AI-SESSION-001`, `AI-EVENT-001`, `AI-STALE-001`, `AI-TIME-001`

이 문서는 사용자가 세운 목표, 목표를 이어 가는 논리 세션, 실제 공부 회차와 관찰 이벤트의 관계를 정의한다. 데이터베이스 Entity나 API가 구현됐다는 뜻은 아니다. 필드와 상태는 Server·Shared·Client 담당자 합의 후 확정한다.

## 1. 해결하려는 문제

`session` 하나로 목표, 한 번의 공부, 타이머 상태와 AI 기억을 모두 표현하면 다음 문제가 생긴다.

- 같은 목표를 다음 날 이어서 공부할 때 새 목표처럼 보인다.
- 일시정지 후 재개와 회차 종료 후 재시작을 구분하기 어렵다.
- 늦게 도착한 AI 결과가 새 회차의 현재 상태를 덮어쓸 수 있다.
- 중복 이벤트와 여러 기기의 동시 명령으로 시간이 이중 집계될 수 있다.
- 목표를 수정했는데 이전 임베딩·캐시·판정이 계속 사용될 수 있다.

따라서 목표와 실행 회차를 분리하고 모든 분석 결과를 원래 관찰 이벤트에 연결한다.

## 2. 개념과 관계

```text
User
└─ GoalProfile (goalId, goalVersion)
   └─ LearningSession (sessionId)
      ├─ SessionRun 1 (runId)
      │  ├─ ActivityEvent A (eventId, navigationId)
      │  │  └─ AnalysisResult
      │  ├─ ActivityEvent B
      │  └─ SessionNote v1
      ├─ SessionRun 2
      └─ 목표 누적 요약과 최신 재개 지점
```

| 개념 | 의미 | 생성·변경 주체 | AI의 권한 |
| --- | --- | --- | --- |
| `GoalProfile` | 사용자가 확인한 목표 해석 | Server가 저장, AI가 후보 생성 | 후보 생성만 가능 |
| `LearningSession` | 한 목표를 장기간 이어 가는 논리 단위 | Server | 조회만 가능 |
| `SessionRun` | 시작부터 회차 종료까지의 실제 공부 단위 | Server | 상태 변경 불가 |
| `ActivityEvent` | 한 페이지·탭·체류 구간의 관찰 단위 | Extension과 Server | 분석 결과만 반환 |
| `AnalysisResult` | 이벤트에 귀속되는 추출·관련성·흐름 결과 | AI, Server 검증 | 생성 가능 |
| `SessionNote` | 종료된 회차의 근거 기반 정리 | AI 후보 생성, Server 저장 | 저장·삭제 불가 |

## 3. GoalProfile 계약

### 3.1 필드 제안

| 필드 | 형식 | 필수 | 규칙 |
| --- | --- | --- | --- |
| `goalId` | UUID 문자열 | 예 | 목표 주제가 바뀌면 새 ID를 사용한다. |
| `goalVersion` | 양의 정수 | 예 | 같은 목표의 의미·범위를 수정할 때 증가한다. |
| `originalText` | 문자열 | 예 | 사용자가 입력한 원문이며 모델이 덮어쓰지 않는다. |
| `mainTopic` | 문자열 | 예 | 목표의 중심 주제 한 개를 제안한다. |
| `purpose` | 제한 enum | 예 | 개념 학습·구현·문제 풀이·오류 해결 등 합의된 값만 사용한다. |
| `coreTopics` | 문자열 배열 | 예 | 직접 관련성을 판단할 핵심 개념이다. |
| `supportingTopics` | 문자열 배열 | 예 | 목표 수행에 필요한 보조 개념이며 무제한 허용 목록이 아니다. |
| `expectedActivities` | 문자열 배열 | 아니요 | 공식 문서·예제·오류 검색처럼 예상 가능한 활동이다. |
| `clarificationNeeded` | Boolean | 예 | 사용자 확인 질문이 필요한지 나타낸다. |
| `confirmedByUser` | Boolean | 예 | Server가 사용자 확인 이벤트로 관리한다. |

### 3.2 생성과 확인

1. 사용자가 목표 원문을 입력한다.
2. AI가 구조화 후보와 필요한 최소 확인 질문을 반환한다.
3. Client가 원문, 주요 주제, 포함할 보조 활동을 보여준다.
4. 사용자가 확인하거나 수정한다.
5. Server가 확인된 Profile을 저장하고 해당 버전만 활성화한다.

사용자 확인 전 Profile은 세션의 확정 판단 기준으로 사용하지 않는다. 단, 미확정 목표로 체험 흐름을 제공한다면 모든 결과를 `NEEDS_CONFIRMATION`으로 제한하는 별도 제품 합의가 필요하다.

### 3.3 버전 증가 규칙

| 변경 | 기본 처리 | 이유 |
| --- | --- | --- |
| 표현만 수정하고 의미가 같음 | 같은 `goalId`, 버전 증가 여부 협의 | 캐시 비용과 감사 가능성의 균형 |
| 보조 주제 추가·삭제 | 같은 `goalId`, `goalVersion + 1` | 관련성 범위가 달라짐 |
| 목적 변경 | 같은 ID 유지 여부 검토, 기본은 버전 증가 | 판단 정책이 달라짐 |
| 중심 주제가 바뀜 | 새 `goalId` | 과거 기록과 의미가 달라짐 |
| 목표 삭제 | 관련 캐시·피드백·노트 파생 참조 삭제 전파 | 삭제 후 복원 방지 |

AI는 방문한 페이지나 반복 검색을 근거로 `supportingTopics`를 자동 추가하지 않는다.

## 4. LearningSession과 SessionRun

### 4.1 논리 세션

하나의 `LearningSession`은 하나의 `goalId`에 연결한다. 목표를 완료·보관·삭제하기 전까지 여러 회차를 가질 수 있다. 목표 버전은 회차 중에도 바뀔 수 있지만, 각 이벤트와 결과에는 사용된 버전을 고정해 기록한다.

제안 상태:

```text
ACTIVE → ARCHIVED
   └──→ COMPLETED
   └──→ DELETED
```

상태 이름과 전이는 Server 계약에서 확정한다.

### 4.2 실제 회차

`SessionRun`은 사용자가 공부를 시작해 명시적으로 회차를 끝내는 단위다.

```text
CREATED → RUNNING ↔ PAUSED → ENDING → COMPLETED
                    └──────────────→ ABORTED
```

| 전이 | 허용 조건 | 멱등 처리 |
| --- | --- | --- |
| 시작 | 활성 목표와 확인된 세션이 있음 | 같은 명령 ID는 기존 회차 반환 |
| 일시정지 | 현재 상태가 `RUNNING` | 이미 `PAUSED`면 현재 Snapshot 반환 |
| 재개 | 현재 상태가 `PAUSED` | 이미 `RUNNING`이면 중복 구간 생성 금지 |
| 종료 | `RUNNING` 또는 `PAUSED` | 같은 종료 명령으로 노트 작업 중복 생성 금지 |
| 중단 | 복구할 수 없는 클라이언트·서버 조건 | 관찰 공백과 마지막 확인 시각 기록 |

초기 정책은 사용자당 활성 `runId` 하나를 제안한다. 여러 기기에서 동시에 시작하려는 경우 Server가 최신 버전과 현재 활성 회차를 반환하며, Client가 기존 회차로 이동할지 종료할지 사용자에게 보여준다.

## 5. ActivityEvent

### 5.1 최소 식별자

- `eventId`: 이벤트 멱등성 키
- `requestId`: 한 API 호출 추적 키
- `sessionId`, `runId`: 소유 세션과 회차
- `goalId`, `goalVersion`: 판단에 사용된 목표
- `navigationId`: 현재 탭 탐색 세대
- `observedAt`: 관찰 시작 또는 대표 시각
- `activeDurationSeconds`: Server가 검증할 관찰 구간 후보

### 5.2 이벤트 불변 조건

- 같은 `eventId`는 한 번만 집계한다.
- 같은 ID에 다른 본문 Fingerprint가 오면 덮어쓰지 않고 충돌로 처리한다.
- 역순 이벤트는 원래 관찰 시각에 연결하되 현재 화면 상태를 바꾸지 않는다.
- 회차 종료 뒤 도착한 분석 결과는 기록 보완용으로만 검토하고 알림을 만들지 않는다.
- `navigationId`가 달라진 캡처·OCR·AI 결과는 `STALE_EVENT`로 폐기한다.
- Client가 보낸 누적 시간을 신뢰하지 않고 Server가 구간을 계산한다.

## 6. 시간 집계

### 6.1 구간 분류

| 구간 | 집계 | 주의점 |
| --- | --- | --- |
| `RELATED` | 직접 학습 시간 후보 | 활성 탭·브라우저 포커스 조건 필요 |
| `SUPPORTING` | 보조 학습 시간 후보 | 정상 학습 합계에 포함 가능 |
| `OFF_TASK` | 목표 무관 시간 후보 | `DRIFT_RISK`와 별도 저장 |
| `UNCERTAIN` | 확인 필요 시간 | 학습·무관 어느 쪽에도 강제 합산하지 않음 |
| `UNAVAILABLE` | 미관찰·분석 불가 시간 | 실패를 무관 시간으로 계산하지 않음 |
| `PAUSED`·휴식 | 비활성 시간 | 학습 시간 제외 |
| `EXCLUDED` | 정책에 따른 내용 없는 구간 또는 미기록 | 콘텐츠를 저장하지 않음 |

추정 학습 시간은 직접 학습 구간과 보조 학습 구간의 합이다. 이 값은 관찰 가능한 브라우저 활동의 추정치이며 실제 이해 시간을 의미하지 않는다.

### 6.2 구간 생성 규칙

- 시작·일시정지·재개·종료·탭 포커스·heartbeat를 기준으로 겹치지 않는 구간을 만든다.
- heartbeat가 끊기면 마지막 확인 이후를 무한 체류로 계산하지 않는다.
- 늦게 도착한 관련성 판정은 원래 구간만 재분류한다.
- 사용자 수정은 명시된 활동 구간만 다시 집계한다.
- 브라우저 밖 활동은 관찰 공백으로 남기고 추정으로 채우지 않는다.
- 집계 변경마다 `aggregationVersion`을 증가시키고 노트 재생성 여부를 판단한다.

## 7. 동시성과 오래된 결과

Server는 세션 명령에 낙관적 버전 또는 동등한 충돌 검사를 사용한다. 요청에 포함된 상태 버전이 최신이 아니면 명령을 적용하지 않고 현재 Snapshot을 반환한다.

AI 결과 적용 전 확인 순서:

1. 사용자와 `sessionId`·`runId` 소유권
2. 회차가 종료·삭제되지 않았는지
3. `goalVersion`이 요청 당시와 같은지
4. `navigationId`와 `eventId`가 현재 또는 원래 구간과 일치하는지
5. 정책·피드백 버전이 결과 생성 뒤 바뀌지 않았는지

실패하면 현재 상태와 알림을 갱신하지 않는다.

## 8. 이어 공부하기

새 회차는 다음 최소 정보만 사용할 수 있다.

- 확인된 최신 GoalProfile
- 직전 회차의 시간·상태 요약
- 사용자가 저장을 허용한 최근 자료 참조
- 사용자가 표시한 미해결 항목
- 같은 목표·콘텐츠 범위의 유효한 피드백

이전 페이지 원문, OCR 원문, 전체 방문 기록과 모델의 숨은 추론은 재개 문맥에 넣지 않는다.

## 9. 삭제와 보존

- 목표 삭제는 세션·회차·피드백·캐시·임베딩·체크포인트·노트의 파생 참조까지 전파한다.
- 회차 기록만 삭제할 때 목표 Profile과 다른 회차를 자동 삭제하지 않는다.
- 콘텐츠 근거가 삭제되면 연결된 노트의 해당 주장을 제거하거나 재생성 필요 상태로 바꾼다.
- 삭제 중인 목표·회차를 비동기 분석이나 노트 작업이 다시 생성하지 못하게 Tombstone 또는 동등한 상태를 확인한다.
- 실제 TTL과 백업 처리 기준은 Server·개인정보 담당자 합의 전까지 미정이다.

## 10. 검증 시나리오

- 같은 목표로 두 번째 회차를 시작해도 과거 시간과 중복되지 않는다.
- 일시정지 명령을 두 번 보내도 중지 구간이 하나만 생긴다.
- 탭 이동 뒤 이전 AI 응답이 도착해도 새 탭 상태를 바꾸지 않는다.
- 목표 수정 뒤 이전 버전 캐시와 임베딩을 사용하지 않는다.
- heartbeat 단절 뒤 무한한 학습 시간이 생기지 않는다.
- 회차 종료를 재시도해도 노트 작업이 하나만 생성된다.
- 사용자 피드백으로 한 구간을 수정해도 다른 목표의 기록이 바뀌지 않는다.
- 삭제된 회차를 늦은 작업이나 재시도가 복원하지 않는다.

## 11. 팀 합의 필요

- 목표당 논리 세션을 하나만 둘지, 보관 후 새 세션을 허용할지
- 사용자당 활성 회차를 하나만 허용할지
- 목적 enum과 목표 버전 증가 조건
- heartbeat 주기와 종료 허용 오차
- 제외 구간과 확인 필요 구간의 사용자 표시 방식
- 낙관적 잠금 필드와 충돌 HTTP 상태
- 회차 기록 수정 가능 기간과 집계 재계산 범위
