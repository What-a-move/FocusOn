## 이번 #29의 개발 순서와 현재 기준

- 기존 AI 코드·테스트·Prompt는 커밋 `0b2c444`에서 초기화했다. 문서와 Issue는 유지한다.
- 첫 단계는 **가짜 세션 데이터 시연**이다. Desktop에서 `종료 → 정리 중 → 결과·복사`, 근거 부족, 실패를 보고, Streamlit은 문서의 DOM 추출 제안 필드(`pageType`, `title`, `text`, `ocr`, `extractionMethod`, `extractionStatus`, `extractorVersion`)와 별도 최종 관련성 판정을 입력받는다. 기본 시연은 화면에 데모임을 명시한다.
- 합성 `text`를 로컬에서 문단으로 나누고, 성공한 DOM 추출·최종 `RELATED`·비민감·중복 제거 결과만 `reviewEvidence`로 만든다. 한 페이지의 서로 다른 문단 2개도 최소 근거 수를 채울 수 있다. 사용자가 OpenAI 버튼을 눌렀을 때 편집한 합성 데이터에서 허용된 짧은 근거만 전송한다. 실제 사용자 화면 데이터는 연결되지 않았다. `gpt-5-mini`는 이 실험의 기본값일 뿐 제품 모델 결정은 아니다.
- 앞선 3회의 OpenAI 형식 탐색 호출은 한 건의 검증 오류와 두 건의 파싱 출력 부재로 끝났다. 출력 토큰 한도를 높인 뒤 기본 합성 DOM 입력 한 건에서 READY 노트를 확인했다. 다양한 실제 DOM 추출 품질을 검증한 것은 아니며, 별도 API 호출 성공을 기능 완료로 간주하지 않는다.
- 실제 `RELATED` 근거, Server 종료·시간 확정·30초 입력 마감, 단일 작업·조회 API는 후속 연결이다. 화면 시연과 합성 데이터 모델 테스트를 #29 완료나 출시로 표현하지 않는다. 실제 화면 데이터의 제공자·보존·사용자 고지 승인은 DOM 추출 및 제품 연동 시점에 논의한다.

## 기능 목적과 책임

확정된 학습 목표와 실제로 목표에 관련된 활동의 최소 근거를 이용해 세션 종료 뒤 짧은 복습 내용을 자동 생성한다. 자료 열람을 이해·구현·문제 해결 완료로 표현하지 않는다.

- Extension/Desktop: 권한·제외·민감 화면을 먼저 검사하고 허용된 최소 텍스트를 추출한다. 원본 DOM·OCR·캡처를 보존하지 않는다.
- AI: 화면 관련성 결과가 `RELATED`인 허용 텍스트에서 최소 `reviewEvidence`를 만들고, Server가 고정한 입력 Snapshot으로 구조화된 정리 후보를 생성한다. 시간 계산과 영구 저장은 하지 않는다.
- Server: 사용자·세션 소유권, 목표 버전, 근거·중복·개인정보, 입력 마감, 비동기 작업, 저장, 재시도, 조회를 담당한다. 세션 종료와 시간 저장은 AI 성공에 의존하지 않는다.
- Desktop 리포트: 상태와 결과를 조회해 생성 중·완료·근거 부족·실패를 구분하고 완료 결과에 복사 버튼을 제공한다.

## MVP 입력 계약

- 세션 시작 시 확정한 `goalSnapshot`과 해당 `sessionId`/`runId`만 사용한다. 목표를 방문 콘텐츠로 자동 확장하지 않는다.
- `RELATED`로 확정된 허용 화면만 근거 후보가 된다. `UNCERTAIN`, `UNRELATED`, `EXCLUDED`, `PRIVACY_BLOCKED`, 분석 실패, 기록 동의 없는 구간은 제외한다.
- `reviewEvidence`에는 개념/키워드, 관찰된 학습 행동의 짧은 의미, 관측 시각, 관련성 신뢰도, 중복 제거 해시만 둔다. 각 근거는 최대 120자, 중복 제거 후 최대 20개, 전체 AI 입력은 최대 2,400자다.
- 원본 DOM·OCR, URL/제목/검색어 전문, 긴 인용, 코드 전체, 비밀값, 개인 메시지, 이미지·카메라 데이터는 입력 Snapshot·DB·Queue·로그에 남기지 않는다.
- 같은 세션의 서로 다른 근거가 2개 미만이면 생성 모델을 호출하지 않고 `INSUFFICIENT_DATA`로 처리한다.

## 생성·출력 계약

1. `ENDED` 확정과 세션 리포트 제공을 먼저 완료한 뒤 정리 상태를 `QUEUED`로 만든다.
2. 종료 후 최대 30초 동안 이미 진행 중이던 분석 결과만 수용하고 `goalSnapshot`과 허용 근거를 고정한다. 이후 도착한 결과로 `READY` 정리를 자동 덮어쓰지 않는다.
3. Server가 작업을 원자적으로 `QUEUED → GENERATING`으로 점유한다. 세션당 정리는 최대 1개다.
4. AI는 `overview`(2~3문장), `keyConcepts`(최대 5개, 각 `name`·`briefExplanation`·`sessionEvidence`), `nextStartPrompt`(한 문장)만 구조화 출력한다. 전체 결과는 1,200자 이하다.
5. 각 서술은 확정된 근거 범위에 묶인다. 관찰되지 않은 세부 지식·이해도·달성도·완료 여부를 덧붙이지 않는다. 자동 복습 질문은 생성하지 않는다.
6. Server가 Schema·길이·근거·URL/토큰/API Key/OTP/이메일/전화번호 패턴을 저장 직전에 검증한다. 민감값이 의심되면 결과 전체를 폐기하며 부분 마스킹해 저장하지 않는다.
7. 사용자 조회 상태는 `QUEUED`, `GENERATING`, `READY`, `INSUFFICIENT_DATA`, `FAILED`다. 생성 모델 Timeout은 20초, 일시 실패는 Backend가 1분·5분 간격으로 최대 2회 재시도한다. 실패해도 세션·시간 기록은 유지한다.

## 기술·구현 순서

1. **화면 시연:** Desktop 기능 PLAN 작성 후 독립 Fixture로 상태·복사 UI를 만든다. Streamlit은 합성 DOM 페이지 필드·RELATED 상태·근거 0/1/2개·중복·제외·민감·동의 철회·실패를 바꿀 수 있게 한다. 기본 시연은 외부 모델을 호출하지 않는다.
2. **계약 정렬:** 후속 탐색용 `AI/docs/session_note_spec.md`와 `AI/docs/api_spec.md`의 다른 상태·재생성·삭제를 MVP와 분리한다. 공유 타입·Notion API·ERD·개인정보 보존/삭제 정책은 담당자 검토 후 일치시킨다.
3. **AI 독립 단위:** 허용 근거 선별·중복 제거·민감값 검사, 구조화 출력·근거 검증과 단위 테스트를 작성한다. 합성 DOM 시험 호출은 `store=false`, 20초 Timeout, SDK 자동 재시도 없음으로 분리한다. 호출 실패·거절·검증 실패는 `FAILED`다. 실제 화면 유래 데이터 전송은 DOM 추출 연동과 팀의 제공자·보존·고지 승인 전 비활성화한다.
4. **Backend 비동기 단위:** PostgreSQL/Flyway의 근거·정리 저장, 세션 소유권 검증, 종료 후 30초 입력 마감, 중복 작업 방지, Worker lease·20초 Timeout·1분/5분 재시도, 결과 재검증, `GET /api/v1/sessions/{sessionId}/learning-summary`를 구현한다. 구체적 Queue 방식과 컬럼은 Backend에서 확정한다.
5. **수집·표시 연동:** #11의 최종 `RELATED`에서만 짧은 근거를 만들고 원본은 버린다. Desktop은 5초 간격으로 진행 상태를 조회하고 terminal 상태에서 멈춘다. 개인정보 승인 후 실제 데이터 통합 테스트를 통과해야 한다.

## 선행 조건·미확정 사항

- 현재 `dev`에는 목표 보조 #12의 AI 실행 코드가 아직 통합되지 않았고 화면 관련성 #11, Extension 추출, Server 세션/API도 미구현이다. 학습 정리 AI 단위는 Fake 입력으로 독립 개발할 수 있지만 제품 전체 동작 완료로 간주하지 않는다.
- Notion 기획은 `REVIEW`다. 루트 `docs/DATA_PRIVACY.md`의 MVP 보존 기준은 정리·노트 1년, 분석 실행·정리 근거 90일이다. 실제 컬럼·삭제 전파, Server↔AI 내부 Schema와 인증, Queue 구현 방식은 담당자 합의가 필요하다.
- 현재 `dev`의 AI 서비스는 빈 골격이다. #29 Streamlit은 제안된 DOM 페이지 형식에서 문단 근거를 만들고, Pydantic 구조화 출력·사후 검증을 거치는 합성 입력 OpenAI 시험 경로를 제공한다. FastAPI 어댑터는 #12 코드 통합 및 내부 인증 계약 확인 뒤 연결한다.
- 합성 데이터 테스트의 기본 모델 `gpt-5-mini`는 학습 정리 제품 모델 선택을 확정하지 않는다. 제품 후보 모델은 실제 데이터 전송 승인과 별도 평가 후 선택한다.
- 화면 관련성 판정 수정·삭제·저장 기반 개인화, 학습 정리의 수동 편집·삭제·재생성, 복습 질문, Graph DB 도입은 이 MVP 기능에서 제외한다.
