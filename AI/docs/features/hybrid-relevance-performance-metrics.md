# FocusOn Hybrid 관련성 판단 성능지표

- 작성일: 2026-10-21
- 상태: 전달용 잠정 보고. 독립 평가와 운영 성능 검증 전
- 대상: 6번 Hybrid — 목표 Graph·별칭 키워드·Qwen 임베딩 코사인 유사도 결합
- 평가 출력: `RELATED`, `UNRELATED`, `UNCERTAIN`

## 1. 보고 요약

최신 추가 테스트는 **확정 목표 5개·합성 사례 20건**이다. 실제 학교 Qwen API 벡터를 받아 기존 Hybrid로 최종 판정했으며 기대 라벨 일치율은 **65.0%(13/20)**, 3개 라벨 Macro F1은 **0.4924**였다. RELATED 8건·UNCERTAIN 12건으로, 무관 사례 5건을 전부 UNCERTAIN으로 유보했다. 따라서 현재 결과로 관련·무관 분류 품질이 확보됐다고 판단할 수 없다.

Graph 준비 이후 분석시간은 평균 **1.424초**, 중앙값 **0.494초**였다. Graph 신규 생성은 목표당 평균 **14.163초**로 별도다. 전체 테스트는 **99.311초**가 걸렸다. 상세 결과는 7절을 따른다. 기존 4건은 3절에 보존했으며 데이터가 달라 25%→65%를 성능 개선으로 비교할 수 없다.

## 2. 사용할 성능지표

| 지표 | 계산·기록 방법 | 확인할 내용 |
| --- | --- | --- |
| 정확도 / 기대 라벨 일치율 | 기대 라벨과 같은 결과 수 ÷ 전체 의미 평가 사례 수 | 전체 일치 정도 |
| Macro F1 | 세 라벨의 F1을 동일 비중으로 평균 | 라벨 수가 다른 경우의 분류 품질 |
| 라벨별 Precision | 해당 라벨 정답 수 ÷ 해당 라벨 예측 수 | 반환한 라벨의 신뢰성 |
| 라벨별 Recall | 해당 라벨 정답 수 ÷ 해당 라벨 기대 사례 수 | 관련·무관 사례를 놓치는 정도 |
| UNCERTAIN 반환율 | UNCERTAIN 결과 수 ÷ 전체 의미 평가 사례 수 | 판정 유보가 과도한지 |
| 학습 자료 무관 오판율 | 기대 RELATED인데 UNRELATED인 수 ÷ 기대 RELATED 수 | 정상 학습을 이탈로 오인하는 정도 |
| 분석 지연 P50·P95 | 입력 수신부터 최종 라벨까지의 중앙값·95백분위 | 일반 지연과 느린 요청의 지연 |
| Graph 생성 지연 | 확정 목표로 Graph 준비를 시작한 시점부터 완료까지 | 최초 목표 설정 대기시간 |
| 요청·실패 수 | 사례별 임베딩/LLM 요청 수, timeout·오류·폴백 수 | 반복 호출과 실패 원인 |

라벨별 `F1 = 2 × Precision × Recall / (Precision + Recall)`이다. 분모가 0인 지표는 이 보고의 집계에서 0으로 처리하고 예측 수를 함께 표시한다. Macro F1은 `[RELATED, UNRELATED, UNCERTAIN]`을 고정해 계산한다. 정의는 [scikit-learn 공식 지표 문서](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.precision_recall_fscore_support.html)를 따른다.

`EXCLUDED`·`PRIVACY_BLOCKED` 같은 정책 결과는 이 3개 라벨 성능에 섞지 않고 별도 검사한다. 실행 실패를 정답 UNCERTAIN으로 계산하지 않는다. Hybrid 결합 점수와 OCR confidence는 정확도나 확률 지표가 아니다. 현재 평가 대상은 최종 라벨 분류이므로 문서 순위 평가용 Recall@K·MRR은 포함하지 않았다.

## 3. 이전 JWT 4건의 잠정 집계

### 평가 조건

- 확정 목표: `JWT 인증 구현`. GoalProfile은 제공하지 않았다.
- 데이터: 직접 작성한 합성 CHROME_DOM 사례 4건. 기대 RELATED 2건·UNRELATED 1건·UNCERTAIN 1건.
- 목표 Graph Prompt: `goal-graph-v3.1`. Graph 관련 개념 8개·무관 주제 3개.
- 임베딩: 학교 API `/api/embed`, 모델 `qwen3-embedding:4b-fp16`, 2560차원 설정.
- 정밀도 F16·revision은 로컬 설정 기준이며 이 평가에서 서버 정보를 재조회하지 않았다.
- 분석: Mac의 기존 Hybrid 코드. 키워드 0.35·벡터 0.65, DIRECT 0.62·PREREQUISITE/SUPPORTING 0.65, 최소 코사인 0.55, 관련 커버리지 0.60·무관 커버리지 0.70·무관 결합 기준 0.75.
- 본문과 기대 라벨은 Graph 생성 입력에 넣지 않았다. 다만 JWT 사례가 Prompt 개선에 사용됐으므로 이 4건은 독립 평가 세트가 아니다.

## 4. 정식 성능 평가에 필요한 작업

1. 여러 확정 목표와 실제 추출 형식의 DOM·OCR 데이터를 준비하고, 개발에 쓰지 않은 자료의 기대 라벨을 사람이 검수한다. 애매한 사례는 검수 기준을 합의한다.
2. 같은 문서의 연속 캡처·유사 문장은 같은 분할에 넣고, 개발 세트와 고정 평가 세트를 분리한다. 현재 JWT 4건은 개발 세트로 유지한다.
3. Prompt·Graph·임계값을 고정한 뒤 평가한다. 다른 유사도 방식 비교가 필요하면 같은 입력·정답·전처리·환경으로 측정한다.
4. 최초 Graph 생성, 개념 벡터 재사용, 결과 캐시 적중을 나눠 반복 측정하고 각각 P50·P95·실패율·요청 수를 보고한다.
5. 정확도 목표와 허용 지연은 팀이 실측을 보고 합의한다. 현재 수치를 출시 합격 기준으로 사용하지 않는다.

## 7. 확정 목표 5개 추가 실측

### 실행 조건과 범위

- 목표 5개를 각각 `confirmed: true`로 설정했다. 목표당 관련 DOM·관련 Desktop OCR·무관 DOM·정보 부족 Chrome OCR 각 1건으로 총 20건이다.
- 기대 라벨은 API 호출 전에 고정했다. Graph는 확정 목표 문장만으로 자동 생성했으며 GoalProfile·미리 정한 템플릿·화면 본문·기대 라벨을 생성에 사용하지 않았다.
- Streamlit이 호출하는 기존 `parse_inputs` → `HybridSession` → `compare(..., ["6"], ...)` → `RelevanceAnalyzer`를 그대로 실행했다. 웹 화면을 자동 조작한 테스트는 아니다.
- Prompt는 `goal-graph-v3.1`, Hybrid는 `school-hybrid-v6`다. 임계값·가중치·별칭 매칭 로직을 바꾸거나 불일치 사례를 수정해 재실행하지 않았다.
- 기존 Client로 학교 `/api/embed`만 호출했다. 제한시간은 60초로 설정했다. 모델 메타데이터 조회 요청은 하지 않았다.
- JSON은 수기로 만든 합성 입력이다. DOM/OCR 실제 추출, Server 인증·공개 API 연동은 이 테스트 범위에 없다. OCR confidence 0.94/0.95는 수동 가정이며 실제 인식 측정값이 아니다. 누락된 세션·관측 ID는 기존 테스트 도구가 합성 문맥으로 채운다.
- 요리 본문과 로딩 본문을 목표마다 동일하게 재사용했다. 평가 조합은 20건이나 고유 본문은 12개이고, 무관 주제는 요리 한 종류뿐이다. 독립 사람 검수나 실사용 일반화 성능을 입증하지 않는다.

Graph 생성 성공은 구조 검증 성공이다. 별칭이 실제 화면 표현을 잘 포괄한다는 의미는 아니다.

### 불일치 7건의 진단

1. **React 관련 DOM·OCR 2건:** 의미상 가까워도 별칭이 본문에 매칭되지 않았다. DOM의 직접 개념 최고 결합점수는 K=0·코사인 0.8445·H=0.5489로 직접 개념 기준 0.62 미달이다. OCR은 K=0·코사인 0.8026·H=0.5217이었다. 관련 본문 커버리지는 모두 0%다. 단순히 커버리지 기준만의 문제가 아니라 앞단 별칭 게이트가 통과되지 않았다.
2. **모든 목표의 요리 DOM 5건:** Graph에 요리 무관 주제는 생성됐지만 아래 본문 매칭이 무관 게이트를 통과하지 못했다. 무관 기준은 K=1·코사인≥0.55·H≥0.75이며, 관련 점수가 낮다는 이유만으로 UNRELATED를 만들지 않는다.

예를 들어 생성 별칭 `요리하기`, `레시피 따라 하기`, `음식 조리`는 본문의 `요리 레시피`, `재료를 볶습니다` 같은 표현과 그대로 일치하지 않는다. 이 20건에서는 Graph 생성 실패·API 실패가 아니라 **별칭 표현 범위와 점수 게이트**가 남은 문제였다. 무관 사례의 낮은 코사인 원인은 이 결과만으로 모델·개념 설명·입력 지침 중 하나로 확정할 수 없다.

## 8. 고정 Graphless 기준의 QueryDSL 불일치 진단

- 실행일: 2026-10-22. 기존 합성 QueryDSL 12건, `goal.text`와 동일한 확정 목표, 실제 학교 Qwen API를 사용했다. 기대 라벨과 본문은 실행 전에 고정했으며 이번 분석에서 수치·산식을 조정하지 않았다.
- 먼저 확인한 화면은 목표 칸이 QueryDSL이지만 JSON은 로드 밸런싱이었다. 화면의 3/12(25%)를 QueryDSL 분류 정확도로 해석할 수 없다. 기존 UI가 이 불일치를 차단하지 못한 문제를 수정했다.
- 현재 UI는 키워드0.20/벡터0.80·관련 H0.60/cosine0.55/커버리지0.60·무관 H0.20/커버리지0.70/최소본문80자를 읽기 전용으로 고정한다.
- 올바른 입력 재현: 기대 일치 7/12(58.33%). RELATED 정답 7건 중 RELATED 2·UNCERTAIN 5, UNRELATED 정답 3건은 모두 UNRELATED, UNCERTAIN 정답 2건은 모두 UNCERTAIN이었다. 관련 자료 재현율은 2/7(28.57%)이다. 모델·추출 실패는 0건이었다.

위 5건의 관련 커버리지는 모두 0이다. 본문 H가 0.60 미만이라 문단이 관련 근거로 등록되지 않은 결과이며, 커버리지 임계값을 낮추는 것으로 해결되지 않는다. 조건 조합 사례는 cosine도 0.55에 미달했다. Q 타입 사례는 H0.5897로 기준보다 약 0.0103 낮다.

현재 목표 키워드는 `querydsl`, `검색`, `조건에`, `따라`, `jpa`, `동적`, `조회`, `쿼리`다. 단순 접미 제거가 `조건에`를 `조건`으로 정리하지 못하고 기능어 `따라`를 포함한다. 표현이 달라지면 적중 수가 낮아지고, 모든 목표 용어가 들어갈 필요가 없는 선수 지식·조인·페이징 자료도 긴 목표의 전체 키워드 수로 나누기 때문에 K가 낮아진다. 점수와 수치상 탈락은 확인된 사실이며, 이를 어떻게 보정할지는 별도 개발 세트 비교가 필요하다.

혼합 `querydsl-55m`은 기대 라벨과 일치하지만 이유는 `INSUFFICIENT_EVIDENCE`였다. 게임 문단의 일반 단어 `검색`이 키워드에 걸려 무관 후보 조건 K=0을 충족하지 못했고, 관련 커버리지 약 51.1%로 보류됐다. 라벨 일치만으로 관련/무관 혼합 감지까지 성공했다고 주장하지 않는다.
