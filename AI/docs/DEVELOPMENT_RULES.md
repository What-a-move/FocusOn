# FocusOn AI 개발 불변 규칙

## 문서 상태

- 상태: 팀 검토용 초안
- 버전: `0.1.0`
- 기준일: 2026-09-12
- 관련 Issue: [#3](https://github.com/What-a-move/FocusOn/issues/3)
- 적용 범위: `AI/`의 코드, 테스트, 평가 데이터, Prompt와 AI API 문서

이 문서는 AI 담당자가 모든 작업에서 반복 확인할 기준을 Rule ID로 정의한다. Notion의 `FocusPath AI 최종 기획서`는 설계 입력이지만 구현 완료나 전원 합의를 뜻하지 않는다. 아래에서 `확정`으로 표시한 규칙만 현재 결정 기록과 공통 개인정보 기준에 근거한 불변 조건이며, `제안`과 `실험`은 관련 담당자 검토 전까지 구현 계약으로 간주하지 않는다.

## 1. 기준 문서와 충돌 처리

작업 시작 시 다음 순서로 문서를 확인한다.

1. 루트 `docs/DATA_PRIVACY.md`와 승인된 공통 API·공유 타입
2. `DECISION_RECORD.md`의 `확정` 결정
3. 이 문서의 `확정` 규칙
4. 현재 GitHub Issue의 범위와 완료 조건
5. `api_spec.md`, `state_model.md`, `analysis_rules.md` 등 검토 중인 상세 초안
6. Notion 기획서와 조사 자료

상위 기준과 하위 초안이 충돌하면 하위 초안을 자동 적용하지 않는다. 충돌을 Issue 또는 PR에 기록하고 담당자 합의 후 `DECISION_RECORD.md`에 새 결정을 추가한다. 기존 확정 결정을 조용히 수정하거나 삭제하지 않는다.

규칙의 의미는 다음과 같다.

- `MUST`: 위반한 상태로 Merge하거나 배포하지 않는다.
- `SHOULD`: 예외가 필요하면 이유와 검증 결과를 PR에 남긴다.
- `MAY`: 평가 결과와 Issue 범위에 따라 선택한다.

| `AI-DRIFT-001` | MUST | 제안 | `OFF_TASK` 한 번만으로 `DRIFT_RISK`, 알림 또는 차단을 결정하지 않는다. 체류, 반복, 최근 흐름, 복귀 여부를 함께 사용한다. | 상태 전이 테스트 |
| `AI-ACTION-001` | MUST | 제안 | 차단과 자동 일시정지는 사용자의 명시적 선택 또는 사전 설정 없이 실행하지 않는다. | 정책·UI 연동 테스트 |
| `AI-STALE-001` | MUST | 제안 | 응답 적용 전에 `goalVersion`, `runId`, `eventId`, `navigationId`와 현재 세션 상태를 재검증하고 오래된 결과를 폐기한다. | 비동기 역순 응답 테스트 |
| `AI-CACHE-001` | MUST | 제안 | 관련성 캐시는 최소한 사용자 범위, 목표 버전, 정제 콘텐츠 해시, 모델·Prompt·추출기·정책·피드백 버전을 구분한다. | 캐시 키·무효화 테스트 |
| `AI-LLM-001` | MUST | 확정 | LLM 출력은 구조화 Schema로 검증한다. LLM에 DB 수정, 브라우저 제어, 임의 URL 방문, 시스템 명령 실행 도구를 제공하지 않는다. | 출력 Schema·도구 허용 목록 검사 |
| `AI-AGENT-001` | MUST | 제안 | Agent는 모호한 요청에만 제한된 읽기 도구를 사용하며 사용자 범위, 도구·모델 호출 수, 재시도와 전체 시간을 강제한다. | Agent 예산·권한 테스트 |
| `AI-FEEDBACK-001` | MUST | 제안 | 명시적 사용자 수정은 같은 사용자·목표 버전·콘텐츠 범위에서 캐시보다 우선하며 페이지 수정이 Domain 전체로 자동 확대되지 않는다. | 피드백 범위·무효화 테스트 |
| `AI-TIME-001` | MUST | 제안 | 학습 시간은 Server의 결정적 로직이 계산한다. LLM은 시간 값을 추정하거나 확정하지 않는다. | 시간 집계 경계 테스트 |
| `AI-NOTE-001` | MUST | 제안 | 학습 노트는 근거 없이 이해, 습득, 해결 완료를 주장하지 않는다. 관찰한 자료와 사용자가 확인한 사실을 구분한다. | 노트 근거 평가 |
| `AI-NOTE-002` | MUST | 제안 | 회차 종료와 시간 저장은 비동기 노트 생성 성공에 의존하지 않으며 중복·stale·삭제된 작업이 노트를 재생성하지 않게 한다. | 노트 멱등성·삭제 테스트 |

| `AI-VISION-002` | MAY | 실험 | PDF·Canvas·이미지·슬라이드처럼 시각 구조가 중요한 콘텐츠에는 ColPali 비교 경로를 사용할 수 있다. | ColPali 기준선 비교 평가 |
| `AI-VISION-003` | MUST | 실험 | ColPali 결과만으로 이탈, 알림, 차단을 결정하지 않는다. Server에서 원본 이미지를 처리하려면 `AI-PRIV-002` 변경과 사용자 동의 검토가 선행되어야 한다. | 보안 설계 리뷰·정책 테스트 |
| `AI-EVAL-001` | MUST | 제안 | 모델, Prompt, 임계값, 전처리, 추출기 또는 상태 의미가 바뀌면 동일 고정 평가 세트로 회귀 평가한다. | 평가 실행 기록 |
| `AI-VERSION-001` | MUST | 제안 | API, 분석기, 모델, Prompt, 추출기, 정책 버전을 분리해 기록하고 호환되지 않는 의미 변경은 Major Version으로 관리한다. | 응답 필드·릴리스 리뷰 |

## 3. 작업 시작 확인

- [ ] GitHub Issue와 Issue 번호가 포함된 Branch를 확인했다.
- [ ] `README.md`, `CONTEXT.md`, `NEXT_TASK.md`, `DECISION_RECORD.md`를 읽었다.
- [ ] 이번 변경에 적용되는 Rule ID를 Issue 또는 작업 메모에 적었다.
- [ ] `확정`, `제안`, `실험`을 구분하고 미합의 값을 구현 상수로 고정하지 않았다.
- [ ] 입력 출처, 수집 위치, 저장 위치, 삭제 경로를 확인했다.
- [ ] Server·Extension·Desktop·공유 타입 중 영향을 받는 소비자를 확인했다.
- [ ] 정상 경로뿐 아니라 실패, 제외, 권한 거부, 오래된 응답 테스트를 계획했다.

## 4. 구현 중 확인

- 원문이나 비밀 값이 로그, 예외 메시지, 테스트 스냅샷에 남지 않게 한다.
- 모델 출력과 페이지 텍스트를 명령으로 취급하지 않는다.
- 임베딩 유사도, OCR 인식 점수, LLM 자기평가를 정답 확률로 혼용하지 않는다.
- 평가되지 않은 임계값과 TTL에는 이름 있는 설정과 `검토 필요` 표시를 사용한다.
- 실패 시 이전 상태를 유지하는 편의 로직이 현재 페이지의 정상 판정처럼 보이지 않게 한다.
- 기능 범위를 넓혀야 하면 현재 Issue에 섞지 않고 별도 Issue 후보로 남긴다.

## 5. 작업 완료 확인

- [ ] 정상·경계·실패·제외·stale 시나리오를 테스트했다.

- [ ] `CONTEXT.md`와 `NEXT_TASK.md`를 실제 구현 상태에 맞게 갱신했다.
- [ ] 테스트 결과, 제한사항, 미합의 항목을 PR에 기록할 준비가 됐다.

## 7. 현재 검토가 필요한 결정

다음 항목은 문서에 제안으로 기록하되 관련 담당자의 합의 전에는 확정하지 않는다.

- 기존 `FocusState`를 호환 필드로 유지할 기간과 제거 조건
- 관련성 분석 최종 경로 `POST /api/v1/sessions/{sessionId}/analysis-runs`의 Server 연동 계약
- 목표당 논리 세션과 다회차 `runId` 구조
- 콘텐츠 캐시, 체크포인트, 진단 로그의 TTL
- 임베딩·LLM 제공자와 외부 전송 조건
- ColPali 실행 위치, 모델 크기, GPU·메모리 예산과 이미지 처리 동의
- 카메라와 자동 일시정지의 최초 출시 포함 여부
- 기능별 PLAN·ERROR·REPORT와 GitHub Issue·PR 역할 정리
