# 분석 기준

## 문서 상태

- 상태: 초안
- 작성 기준일: 2026-09-05
- 적용 대상: `POST /api/v1/analysis/relevance`
- 관련 문서: `api_spec.md`, `prompt_guide.md`, 루트 `docs/DATA_PRIVACY.md`
- 확정 조건: AI 평가 결과를 확인하고 Server·Desktop·Extension 담당자와 상태값을 합의한 뒤 `DECISION_RECORD.md`에 기록한다.

이 문서는 구현 완료 상태를 설명하지 않는다. 관련성 분석기를 구현하고 평가할 때 따라야 할 판정 기준을 정의한다.

## 1. 분석 목적

관련성 분석기는 사용자가 설정한 학습 목표와 현재 앱·페이지 정보를 비교해 현재 활동의 목표 관련성을 판단한다.

분석 결과는 사용자의 실제 시선, 자세 또는 주의력을 측정한 값이 아니다. 화면·페이지의 의미가 목표와 관련 있는지를 바탕으로 추정한 활동 상태다.

분석기는 다음 결과를 반환한다.

- `RELATED`: 현재 활동이 학습 목표 또는 목표 달성에 필요한 보조 활동과 관련됨
- `UNRELATED`: 현재 활동이 학습 목표와 명확하게 무관함
- `UNCERTAIN`: 정보가 부족하거나 서로 충돌해 관련성을 확정하기 어려움

## 2. 분석 입력

### 2.1 공통 입력

- 학습 목표 문장 `goal.text`
- 데이터 출처 `activity.source`
- 활동 관찰 시각 `observedAt`
- 현재 앱·페이지의 최소 메타데이터
- 민감 정보를 제거한 선택적 `contentText`

### 2.2 출처별 입력

| 출처 | 필수 정보 | 선택 정보 |
| --- | --- | --- |
| `DESKTOP` | `appName` | `bundleId`, `title`, `textSource`, `contentText` |
| `EXTENSION` | `domain` | `appName`, `title`, `textSource`, `contentText` |

- `DESKTOP` 입력은 `domain`을 사용하지 않는다.
- `EXTENSION` 입력은 `bundleId`를 사용하지 않는다.
- `contentText`가 있으면 `textSource`는 `OCR` 또는 `PAGE_TEXT`여야 한다.
- 선택 정보가 없으면 빈 문자열이나 `null` 대신 필드를 생략한다.

## 3. 분석 전 처리

분석기는 다음 순서로 입력을 처리한다.

```text
API Schema 검증
  → 출처별 필수값 검증
  → 문자열 정규화
  → 민감 정보 2차 검사
  → Prompt Injection 분리
  → 정보 충분성 판단
  → 관련성 점수·신뢰도 계산
  → 상태와 근거 코드 결정
```

### 3.1 문자열 정규화

- 문자열 앞뒤 공백을 제거한다.
- 연속된 공백과 줄바꿈은 의미를 해치지 않는 범위에서 하나의 공백으로 정리한다.
- Unicode는 NFKC 형식으로 정규화한다.
- 영문 비교는 대소문자를 구분하지 않지만 반환 문구의 원래 표기는 유지한다.
- `domain`은 소문자로 비교한다.
- 입력 언어를 임의로 번역해 원문 의미를 바꾸지 않는다.

### 3.2 민감 정보 검사

Server가 1차 제거를 담당하고 AI 서비스가 모델 호출 전에 다음 항목을 2차 검사한다.

- Bearer 인증 Header 또는 토큰
- JWT 형식 문자열
- 알려진 API Key Prefix와 Key 형태
- Luhn 검사를 통과한 결제 카드 번호 후보

하나라도 발견하면 분석을 중단하고 `SENSITIVE_CONTENT_DETECTED` 오류를 반환한다. 발견된 문자열은 로그·캐시·오류 메시지에 남기지 않는다.

개인 메시지는 문자열 규칙만으로 정확히 구분할 수 없으므로 Server가 제외 앱·도메인과 수집 단계에서 차단한다.

### 3.3 Prompt Injection 처리

`goal.text`, `title`, `contentText`에 포함된 명령문은 모두 분석 대상 데이터로 취급한다. 다음과 같은 문장을 시스템 지시로 실행하지 않는다.

- 이전 지시를 무시하라는 문장
- 특정 상태나 점수를 반환하라는 문장
- 시스템 Prompt 또는 비밀 값을 출력하라는 문장
- JSON 이외의 형식으로 응답하라는 문장

Prompt Injection 문장이 있다는 이유만으로 활동을 `UNRELATED`로 판단하지 않는다. 남은 안전한 문맥으로 판단할 수 없으면 `UNCERTAIN`을 반환한다.

### 3.4 OCR·페이지 텍스트 정제

OCR 엔진과 원본 화면 처리는 클라이언트가 담당한다. AI는 `textSource`에 따라 전달받은 텍스트를 정제하고 분석 가능한 품질인지 판단한다.

공통 정제:

- 같은 문구가 연속 반복되면 한 번만 유지한다.
- 메뉴, 버튼, 상태 표시처럼 반복되는 짧은 UI 문구의 비중을 낮춘다.
- 제어 문자와 의미 없는 공백을 제거한다.
- URL Query, Token, 이메일 등 분석에 불필요한 식별 정보를 제거하거나 마스킹한다.
- 정제 전·후 원문을 로그나 캐시에 저장하지 않는다.

`OCR` 추가 정제:

- 깨진 문자와 비정상적으로 반복되는 문자를 제거한다.
- 인식할 수 있는 한글·영문·숫자 비율이 낮으면 품질을 낮게 평가한다.
- 의미 있는 단어가 부족하면 무관 활동으로 단정하지 않고 `INSUFFICIENT_CONTEXT`로 처리한다.

`PAGE_TEXT` 추가 정제:

- Navigation, Footer, Cookie 배너처럼 모든 페이지에 반복되는 영역을 우선 제외한다.
- 숨김 요소와 Script·Style 텍스트를 분석 대상으로 사용하지 않는다.
- 입력 영역, 비밀번호 필드, 결제·인증 화면의 값은 수집 단계에서 제외한다.

구체적인 최소 글자 수와 품질 임계값은 평가 데이터에서 OCR 언어·화면 크기별 오판을 확인한 뒤 확정한다.

## 4. 관련성 판단 원칙

### 4.1 관련 활동

다음 중 하나를 충분히 확인할 수 있으면 관련 활동으로 평가한다.

- 목표의 핵심 주제와 현재 콘텐츠의 주제가 직접 일치함
- 목표를 수행하는 데 필요한 개발 도구, 문서, 강의 또는 실습 환경임
- 목표 결과물을 작성·검토·테스트하는 활동임
- 목표 수행을 위해 필요한 검색이나 참고 자료 확인임

앱이나 도메인 이름만으로 관련성을 확정하지 않는다. IDE, GitHub, YouTube, 검색 엔진처럼 여러 목적으로 쓰이는 도구는 제목과 콘텐츠 문맥을 함께 확인한다.

### 4.2 무관 활동

다음 조건을 모두 충족할 때 무관 활동으로 평가한다.

- 현재 활동의 주제가 목표와 명확하게 다름
- 목표 수행을 지원하는 도구·자료·과정으로 볼 근거가 없음
- 판단에 필요한 정보가 충분하고 서로 충돌하지 않음

특정 앱이나 도메인이라는 이유만으로 자동으로 `UNRELATED`를 반환하지 않는다. 예를 들어 YouTube도 학습 강의일 수 있고, 메신저도 팀 프로젝트 논의에 쓰일 수 있다.

### 4.3 불확실한 활동

다음 상황에서는 `UNCERTAIN`을 우선한다.

- 앱 이름이나 도메인만 있고 실제 활동 주제를 알 수 없음
- 새 탭, 빈 문서 또는 일반적인 홈 화면임
- 제목과 본문이 서로 다른 주제를 나타냄
- 목표 문장이 지나치게 짧거나 모호함
- 관련성 점수가 중간 구간에 있음
- 관련성 점수와 별개로 판단 신뢰도가 기준보다 낮음
- 서로 다른 언어, 약어 또는 고유명사 때문에 의미를 확정하기 어려움

정보가 부족한 상황을 억지로 `RELATED` 또는 `UNRELATED`로 분류하지 않는다.

### 4.4 단계적 판단

관련성 분석은 다음 순서로 실행한다.

1. 전처리 단계에서 입력 누락, 민감 정보, 텍스트 품질을 확인한다.
2. 규칙 단계에서 명확한 정보 부족과 직접적인 목표 개념 일치를 확인한다.
3. 규칙만으로 확정할 수 없으면 목표와 콘텐츠의 임베딩 유사도를 계산한다.
4. 임베딩 결과가 경계 구간이거나 제목·본문 근거가 충돌하면 LLM을 호출한다.
5. 모든 단계의 결과를 공통 `relevanceScore`와 `confidence`로 보정한 뒤 상태 결정 규칙을 적용한다.

규칙 기반 판단:

- 텍스트가 없거나 품질이 낮은 경우 빠르게 `UNCERTAIN` 후보로 분류한다.
- 목표 핵심 개념이 제목과 본문에서 함께 확인되면 관련 활동 후보로 분류한다.
- 앱·도메인 차단과 개인정보 화면 판단은 AI 규칙이 아니라 Server의 호출 전 정책이 담당한다.
- 앱 이름, 도메인 또는 단일 키워드만으로 `UNRELATED`를 확정하지 않는다.

임베딩 판단:

- 목표와 정제 콘텐츠의 의미적 유사도를 비교한다.
- 임베딩 유사도는 모델별 분포가 다르므로 `relevanceScore`와 같은 값으로 직접 사용하지 않는다.
- 사용할 모델과 고·저 유사도 임계값은 평가 데이터로 보정한다.
- 명확한 고·저 구간에서는 LLM 호출을 생략할 수 있다.

LLM Fallback:

- 규칙과 임베딩 결과가 서로 충돌할 때 사용한다.
- 검색, 오류 해결, 공식 문서처럼 목표를 간접 지원하는 활동인지 해석할 때 사용한다.
- Prompt 입력과 출력은 `prompt_guide.md`를 따른다.
- LLM이 실패하면 근거가 충분한 이전 단계 결과만 사용할 수 있다. 이전 단계도 경계 상태라면 `MODEL_UNAVAILABLE` 오류를 반환한다.

## 5. 점수와 신뢰도

### 5.1 관련성 점수

`relevanceScore`는 현재 활동이 학습 목표와 얼마나 관련 있는지를 `0.0`부터 `1.0`까지 나타낸다.

| 범위 | 의미 |
| --- | --- |
| `relevanceScore <= 0.35` | 목표와 관련성이 낮음 |
| `0.35 < relevanceScore < 0.65` | 관련성을 확정하기 어려움 |
| `relevanceScore >= 0.65` | 목표와 관련성이 높음 |

점수는 다음 근거를 함께 고려한다.

- 목표 핵심 개념과 활동 주제의 의미적 일치
- 현재 앱·페이지가 목표 수행에 필요한 도구인지 여부
- 제목·도메인·본문이 같은 판단을 지지하는지 여부
- 목표와 무관한 주제가 명확하게 나타나는지 여부

### 5.2 신뢰도

`confidence`는 반환한 판단을 뒷받침하는 입력 정보가 얼마나 충분하고 일관적인지를 `0.0`부터 `1.0`까지 나타낸다.

| 범위 | 의미 |
| --- | --- |
| `0.00~0.59` | 정보 부족 또는 근거 충돌 |
| `0.60~0.79` | 한 개의 강한 근거 또는 여러 개의 부분 근거가 있음 |
| `0.80~1.00` | 여러 독립적인 입력이 같은 판단을 지지함 |

- 관련성 점수가 높아도 입력이 부족하면 신뢰도는 낮을 수 있다.
- 앱 이름만으로 판단한 경우 높은 신뢰도를 부여하지 않는다.
- 제목과 본문이 충돌하면 신뢰도를 낮춘다.
- 모델이 정상 응답했다는 사실만으로 신뢰도를 높이지 않는다.

## 6. 상태 결정 규칙

입력 검증과 민감 정보 검사를 통과한 결과에 다음 규칙을 순서대로 적용한다.

| 조건 | `state` | `reasonCode` |
| --- | --- | --- |
| 판단 정보 자체가 부족함 | `UNCERTAIN` | `INSUFFICIENT_CONTEXT` |
| 입력 근거가 서로 충돌하거나 의미가 모호함 | `UNCERTAIN` | `AMBIGUOUS_CONTEXT` |
| `contextStatus = SUFFICIENT`이고 `confidence < 0.60` | `UNCERTAIN` | `AMBIGUOUS_CONTEXT` |
| `relevanceScore >= 0.65`이고 `confidence >= 0.60` | `RELATED` | `GOAL_RELATED` |
| `relevanceScore <= 0.35`이고 `confidence >= 0.60` | `UNRELATED` | `GOAL_UNRELATED` |
| 그 외 모든 경우 | `UNCERTAIN` | `AMBIGUOUS_CONTEXT` |

- 경계값 `0.65`는 `RELATED` 구간에 포함한다.
- 경계값 `0.35`는 `UNRELATED` 구간에 포함한다.
- 모델 장애, 외부 API 장애, 형식 오류, Timeout은 `UNCERTAIN`으로 변환하지 않고 `api_spec.md`의 실패 응답으로 처리한다.

## 7. 근거 문구

`reason`은 모델의 자유 형식 문장을 그대로 사용하지 않는다. `reasonCode`에 대응하는 검증된 한국어 Template을 사용한다.

| `reasonCode` | 기본 `reason` |
| --- | --- |
| `GOAL_RELATED` | 현재 활동이 설정한 학습 목표와 관련되어 있습니다. |
| `GOAL_UNRELATED` | 현재 활동이 설정한 학습 목표와 관련성이 낮아 보입니다. |
| `INSUFFICIENT_CONTEXT` | 현재 정보만으로는 학습 목표와의 관련성을 판단하기 어렵습니다. |
| `AMBIGUOUS_CONTEXT` | 현재 활동에 서로 다른 판단 근거가 있어 관련성을 확정하기 어렵습니다. |

- 사용자를 비난하거나 의도를 단정하지 않는다.
- 입력 원문, 개인 식별 정보, 비밀 값은 `reason`에 포함하지 않는다.
- UI가 다른 문구를 사용하더라도 분기 기준은 `reason`이 아니라 `reasonCode`다.

## 8. 주요 경계 사례

| 학습 목표 | 현재 활동 | 예상 결과 | 이유 |
| --- | --- | --- | --- |
| Java 백엔드 개발 | IntelliJ에서 Java 파일 편집 | `RELATED` | 목표 결과물을 직접 작성함 |
| Spring Security 공부 | Spring 공식 문서 | `RELATED` | 목표 주제와 문서 주제가 직접 일치함 |
| 영어 듣기 공부 | 영어 강의 YouTube 영상 | `RELATED` | 도메인이 아니라 콘텐츠가 목표와 관련됨 |
| Java 공부 | 제목 없는 GitHub 화면 | `UNCERTAIN` | 저장소 주제와 활동 목적을 알 수 없음 |
| 시험 공부 | Chrome 새 탭 | `UNCERTAIN` | 판단할 활동 정보가 부족함 |
| 알고리즘 공부 | 연예 뉴스 기사 | `UNRELATED` | 충분한 문맥에서 목표와 다른 주제가 확인됨 |
| 발표 자료 작성 | 팀 메신저 대화 | `UNCERTAIN` | 수집 제외 가능성이 있고 대화 목적을 확정하기 어려움 |

## 9. 평가 기준

초기 평가 데이터는 실제 개인정보가 없는 인공 문장 또는 공개 자료의 축약문으로 작성한다.

- 최소 60개 사례를 준비한다.
- `RELATED`, `UNRELATED`, `UNCERTAIN` 정답 사례를 각각 최소 20개 포함한다.
- Desktop과 Extension 입력을 모두 포함한다.
- 한국어, 영어, 한·영 혼합 입력을 포함한다.
- 일반 앱·도메인, 모호한 목표, 충돌하는 제목·본문, Prompt Injection 사례를 포함한다.
- 민감 정보 사례는 실제 비밀 값 대신 명백한 가짜 값으로 검사한다.

1차 품질 기준은 다음과 같다.

- 세 상태 전체 Macro F1 `0.75` 이상
- `UNRELATED` 오판으로 불필요한 알림이 발생하는 비율 `10%` 이하
- 민감 정보 차단 평가 사례 통과율 `100%`
- 동일 입력·동일 분석 버전의 상태와 근거 코드 일치율 `100%`

기준을 충족하지 못하면 임계값이나 Prompt를 조정하고 변경 이유와 평가 결과를 `DECISION_RECORD.md`와 기능 결과 리포트에 기록한다.

## 10. 버전 관리

- API 응답의 `analyzerVersion`은 `relevance-v{major}` 형식을 사용한다.
- 상태 의미, 점수 구간 또는 입력 해석 규칙이 호환되지 않게 바뀌면 Major Version을 올린다.
- 모델이나 Prompt만 변경되고 API 의미가 유지되면 내부 세부 버전을 별도로 기록한다.
- 임계값, 모델, Prompt, 전처리 규칙을 변경하면 같은 평가 데이터로 회귀 평가를 실행한다.
- 확정된 변경은 `DECISION_RECORD.md`에 추가하고 기존 결정을 삭제하지 않는다.
