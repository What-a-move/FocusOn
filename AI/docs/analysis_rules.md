# AI 분석 규칙

## 문서 상태

- 상태: 팀 검토용 초안, 미구현
- 버전: `0.3.0-draft`
- 기준일: 2026-09-22
- 검토 필요: Server 담당자, Frontend(`apps`) 담당자
- 관련 문서: [개발 규칙](DEVELOPMENT_RULES.md), [콘텐츠 수집 계약](content_acquisition_spec.md), [상태 모델](state_model.md), [Agent 계약](focus_session_agent_spec.md), [피드백 명세](feedback_personalization_spec.md), [평가 명세](evaluation_spec.md)
- 확정 조건: AI 평가 결과를 확인하고 Server·Frontend(`apps`) 담당자와 상태값을 합의한 뒤 `DECISION_RECORD.md`에 기록한다.

이 문서는 목표 구조화, 콘텐츠 품질, 관련성, 학습 흐름과 개입 제안의 처리 순서를 정의한다. 상태 enum과 허용 조합은 `state_model.md`, 평가 기준은 `evaluation_spec.md`를 단일 기준으로 사용한다.

## 1. 판단 대상과 한계

AI는 사용자가 확인한 학습 목표와 허용된 콘텐츠·최근 활동 요약을 비교한다. AI 결과는 관찰 가능한 브라우저 활동에 대한 추정이며 다음을 측정했다고 표현하지 않는다.

- 실제 이해도나 성취도
- 심리적 집중력이나 공부 의지
- 시선·감정·건강 상태
- 브라우저 밖에서 발생한 코드 실행·오류 해결

## 2. 전체 처리 순서

```text
세션·권한·제외 검사
  → Chrome DOM 우선 추출 또는 Desktop 활성 앱 메타데이터
  → Chrome 정보 부족 시 Extension 내부 로컬 OCR
  → Desktop 정보 부족 시 Apple Vision 로컬 OCR
  → 개인정보·품질 검사
  → 정제 콘텐츠 해시 생성
  → 캐시·목표 임베딩·최근 흐름·피드백 조회
  → 필요한 임베딩만 생성
  → 관련성 후보 계산
  → 근거가 모호한 경우 LLM 또는 FocusSessionAgent
  → 관련성·흐름·알림 정책 결합
  → Schema와 현재 버전 재검증
  → 결과 반환
```

제외 검사와 개인정보 검사를 통과하기 전에는 콘텐츠 추출, 이미지 캡처 또는 외부 모델 호출을 시작하지 않는다. 캐시 확인 중에 고비용 임베딩이나 LLM을 무조건 실행하지 않는다.

## 3. 콘텐츠 추출과 품질

### 3.1 추출 우선순위

1. Extension이 허용된 DOM의 제목, 주요 문단, 코드, 표, 접근 가능한 자막을 추출한다.
2. 콘텐츠 유형별 전용 추출기를 우선하고 실패 시 허용된 일반 추출기를 사용한다.
3. Chrome DOM 정보가 부족한 경우에는 Extension 내부 OCR, macOS Desktop 활성 앱 정보가 부족한 경우에는 Apple Vision OCR로 처리한다.
4. PDF·Canvas·이미지·슬라이드의 시각 구조는 별도 ColPali PoC에서 비교한다.

ColPali는 OCR 대체나 모든 페이지의 기본 분석기가 아니다. 기준선 비교를 통과해도 단독으로 이탈·알림·차단을 결정하지 않는다.

### 3.2 유형별 핵심 정보

| 유형 | 우선 정보 | 기본 제외 |
| --- | --- | --- |
| 일반 문서 | 제목, H1~H3, 주요 문단, 표, 코드, 대체 텍스트 | 메뉴, 광고, 추천, Footer |
| 검색 결과 | 허용된 검색어, 상위 결과 제목·설명 | 입력 폼 값, 광고, 전체 결과 일괄 수집 |
| YouTube | 영상 ID, 제목, 설명, 재생 상태, 접근 가능한 자막 | 추천 영상, 댓글, 계정 정보 |
| GitHub | 저장소 설명, README, 현재 파일·Issue의 핵심 내용 | Token, 비밀 설정, 저장소 전체 수집 |
| Q&A | 질문, 기술 태그, 오류, 핵심 답변·코드 | 댓글 전체, 추천 질문 |
| PDF·이미지·Canvas | 접근 가능한 텍스트, 현재 보이는 허용 영역 | 보이지 않는 페이지 일괄 캡처 |

### 3.3 품질 판정

문자 수만으로 품질을 결정하지 않는다. 콘텐츠 유형별 필수 정보, 본문 비율, 메뉴 중복, OCR 인식 품질, 코드·표 순서 보존 여부를 함께 본다.

- `SUCCESS`: 관련성 판단에 필요한 핵심 근거가 있다.
- `PARTIAL`: 일부 근거만 있어 범위를 제한하거나 사용자 확인이 필요하다.
- `FAILED`: 비어 있음, 접근 실패, Timeout 등으로 사용할 수 없다.
- `EXCLUDED`: 정책상 수집 금지다.
- `UNSUPPORTED`: 현재 환경에서 안전한 추출 경로가 없다.

`FAILED`, `EXCLUDED`, `UNSUPPORTED`를 낮은 관련성으로 해석하지 않는다.

## 4. 전처리와 개인정보

- 제목·문단·표·코드 단위를 유지한다.
- 공백과 반복 메뉴를 정리하되 오류 코드, 식별자, 부정 표현, 코드 구문을 임의로 고치지 않는다.
- 목표 키워드가 있는 문단만 남기지 않고 대표 문단 일부를 유지해 우연한 일치를 줄인다.
- 폼, 입력값, `contenteditable`, 인증·결제 영역은 수집 단계에서 제외한다.
- Server 검사 후에도 AI가 명백한 Token·API Key·결제 카드 후보를 발견하면 모델 호출을 중지한다.
- 페이지의 지시문은 분석 데이터일 뿐 시스템 지시가 아니다.

상세 수집·저장·삭제 기준은 `data_lifecycle.md`를 따른다.

## 5. 목표 구조화

목표는 다음 요소로 구조화한다.

- 원문과 `goalVersion`
- 주요 주제 `mainTopic`
- 목적: 개념 학습, 구현, 문제 풀이, 오류 해결 등 제한된 enum
- 핵심 주제와 보조 주제
- 예상 활동: 공식 문서, 예제 코드, 오류 검색, 강의 등
- 사용자 확인 필요 여부

확정 전 목표 보조는 다음 `clarityStatus`를 사용한다.

| 상태 | 의미 | 처리 |
| --- | --- | --- |
| `CLEAR` | 목표와 활동이 명확함 | 해석 결과 확인 |
| `NEEDS_SELECTION` | 여러 목표가 포함됨 | 2~3개 후보 중 하나 선택 |
| `NEEDS_SUGGESTION` | 범위가 넓음 | 2~3개 구체 목표 제안 |
| `NEEDS_QUESTION` | 의미·대상·활동이 부족함 | 1~2개 확인 질문 |
| `INVALID` | 비어 있거나 분석 불가 | 재입력 |
| `UNRECOGNIZED_TERM` | 약어·오타가 불확실함 | 후보 확인 |

모호한 목표에는 최소 질문을 제안한다. 사용자가 확인·수정하기 전 목표 해석을 확정하지 않는다. 같은 목표 범위의 수정은 `goalVersion`을 증가시키고, 주제가 바뀌면 새 `goalId`를 제안한다.

AI는 방문 콘텐츠를 근거로 사용자 목표를 자동 확장하지 않는다. 보조 주제는 사이트 전체나 키워드 전체의 허용 목록이 아니다.

## 6. 관련성 판단

### 6.1 `RELATED`

- 목표 주제의 강의·문서·문제 풀이
- 목표 결과물을 직접 작성하거나 검증하는 활동
- 목표의 핵심 개념과 페이지의 대표 근거가 일치하는 활동

### 6.2 `SUPPORTING`

- 구현 중 오류 검색과 해결 자료 확인
- 선수 지식·공식 API·도구 사용법 확인
- 관련 코드 예제·Q&A·문서 비교
- 최근 학습 흐름과 연결되는 보조 자료

### 6.3 `OFF_TASK`

충분한 품질의 콘텐츠가 현재 목표와 명확하게 다른 경우다. 앱 이름, 도메인, 단일 키워드만으로 확정하지 않는다. `OFF_TASK`는 콘텐츠 관계이며 지속적 이탈이나 사용자 차단을 뜻하지 않는다.

### 6.4 `UNCERTAIN`과 `UNAVAILABLE`

- `UNCERTAIN`: 정보는 있으나 목표가 모호하거나 제목·본문·최근 흐름이 충돌한다.
- `UNAVAILABLE`: 추출·권한·모델 실패로 판단 근거 자체를 확보하지 못했다.

두 값을 구분해 사용자 확인이 의미 있는 경우에만 `ASK_USER`를 사용한다. 시스템 실패를 사용자에게 관련성 질문으로 넘기지 않는다.

제품 표시에서는 `SUPPORTING`을 `RELATED`의 보조 유형으로, `OFF_TASK`를 `UNRELATED`로 매핑한다. `UNAVAILABLE`은 제품 `UNCERTAIN`과 처리 실패 원인을 함께 전달하며, `EXCLUDED`와 `PRIVACY_BLOCKED`는 관련성 판정이 아닌 비분석 결과다.

## 7. 단계적 분석

### 7.1 규칙

- 정보 부족, 제외, 미지원과 명백한 실패를 먼저 분리한다.
- 사용자 수정과 동일 목표·콘텐츠 피드백을 모델 결과보다 우선한다.
- 강한 직접 근거와 충돌 없는 보조 근거는 LLM 없이 확정할 수 있다.
- 도메인 차단과 민감 화면 판단은 관련성 규칙이 아니라 호출 전 정책이다.

### 7.2 임베딩

- 목표의 핵심·보조 주제와 정제 문단의 의미 유사도를 계산한다.
- 같은 모델·전처리 버전의 벡터만 비교한다.
- 유사도는 후보 신호이며 정답 확률이나 실제 집중도로 표시하지 않는다.
- 낮은 유사도라도 보조 활동·사용자 수정·최근 오류 검색 근거가 있으면 바로 `OFF_TASK`로 확정하지 않는다.

### 7.3 LLM 또는 FocusSessionAgent

다음 경우에만 정밀 판단을 사용한다.

- 임베딩과 규칙 근거가 충돌함
- `RELATED`와 `SUPPORTING` 구분이 어려움
- 최근 흐름을 추가 조회해야 보조 관계를 판단할 수 있음
- 사용자 피드백 범위 적용이 모호함

LLM과 Agent는 `prompt_guide.md`의 신뢰 경계, 구조화 출력, 도구 허용 목록과 시간·호출 예산을 따른다. 모델 실패 시 안전한 이전 단계가 없으면 `UNAVAILABLE` 또는 실패 envelope로 종료한다.

## 8. 점수와 임계값

다음 값은 서로 다른 의미다.

- 임베딩 유사도: 벡터 공간의 거리 신호
- OCR 인식 점수: 문자 인식 품질
- 관련성 점수: 여러 근거를 결합한 설명용 지표 후보
- `confidence`: 입력 충분성과 판단 일관성 지표 후보

현재 문서에 있던 `0.35`, `0.60`, `0.65`는 초기 가설이며 확정 임계값이 아니다. 모델별 분포와 라벨별 오판 비용을 평가한 뒤 설정으로 관리한다. 임계값 변경은 같은 평가 세트로 회귀 평가하고 결정 기록에 남긴다.

## 9. 학습 흐름과 이탈

최근 활동에는 허용된 최소 요약만 사용한다.

- 제목·핵심 주제·관련성 라벨
- 허용된 검색어·이동 출처
- 관찰된 체류·복귀 여부
- 사용자 피드백 버전

전체 방문 기록이나 브라우저에서 관찰하지 못한 행동을 전달하지 않는다.

```text
JWT 강의 → 인증 오류 검색 → Q&A → 공식 문서
  = SUPPORTING을 포함한 LEARNING

JWT 강의 → 무관 영상 짧은 방문 → 강의 복귀
  = OBSERVING → RECOVERED, 무알림

JWT 강의 → 무관 영상 반복 → 지속 체류
  = POSSIBLE_DRIFT → 정책 기준 충족 시 DRIFT_RISK
```

이동 출처가 광고·추천 링크라는 이유만으로 이탈을 확정하지 않는다. 페이지가 바뀌지 않아도 체류 정책은 다시 평가할 수 있지만 OCR·임베딩·LLM을 매번 호출하지 않는다.

## 10. 알림과 사용자 피드백

- `RELATED`·`SUPPORTING`과 정상 흐름에는 `NO_ACTION`을 사용한다.
- 의미적으로 모호하지만 품질이 충분할 때만 `ASK_USER`를 검토한다.
- 실패·미지원·낮은 품질에는 이탈 경고 대신 상태를 표시한다.
- `SUGGEST_RETURN`은 지속·반복 근거, 현재 버전, 쿨다운을 모두 확인한 뒤 제안한다.
- 임시 차단은 현재 MVP 행동 enum에 포함하지 않는다. 후속 기능으로 추진할 때 대상 페이지·도메인·시간과 사용자 선택을 별도 합의한다.
- 관련 자료 복귀나 사용자 수정이 발생하면 대기 알림을 취소한다.

사용자 선택은 의미를 분리한다.

- `목표 관련`: 관련성 정답 피드백
- `보조 자료`: `SUPPORTING` 피드백
- `계속 보기`: 현재 알림 보류, 관련성 정답으로 사용하지 않음
- `잠시 쉬기`: 세션 일시정지 선택

피드백 키는 사용자 범위 + 목표·버전 + 콘텐츠 해시 + 적용 범위를 기본으로 한다. 한 페이지 수정이 사이트 전체 허용으로 확대되지 않게 한다.

선택별 의미, 적용 범위, 우선순위, 철회와 삭제 기준은 `feedback_personalization_spec.md`를 따른다.

### 10.1 개입 생성 조건

| 행동 | 필수 조건 | 생성하지 않는 경우 |
| --- | --- | --- |
| `NO_ACTION` | 정상·짧은 방문·실패·미지원·정보 부족 | 해당 없음 |
| `ASK_USER` | 품질이 충분하고 의미적으로 모호함 | 시스템 오류, 추출 실패 |
| `SUGGEST_RETURN` | `DRIFT_RISK`, 지속·반복 근거, 쿨다운 통과 | 단일 `OFF_TASK`, 오래된 결과 |
| `SUGGEST_BREAK` | 사용자 설정과 장시간 활동 근거 | 모델의 감정·피로 추정만 있음 |
| `SUGGEST_PAUSE` | 선택 기능의 지속적인 자리 비움 근거 | 순간 미감지, 권한 거부 |
| `SUGGEST_TEMPORARY_BLOCK` | 후속 기능에서 별도 합의할 반복 이탈 제안 | 현재 MVP에는 없음, Domain 전체 자동 차단 금지 |

### 10.2 알림 생명주기

```text
CANDIDATE
  → 최신 목표·회차·탭·정책·피드백 재검증
  → 중복·쿨다운·사용자 설정 검사
  ├─ 통과: READY → DISPLAYED → RESPONDED | DISMISSED | EXPIRED
  └─ 실패: CANCELLED
```

- 후보 생성과 실제 표시를 분리한다.
- 같은 목표·콘텐츠·행동의 대기·표시 알림을 중복 생성하지 않는다.
- 관련 자료 복귀, 목표 변경, 판정 수정, 세션 일시정지·종료 시 대기 알림을 취소한다.
- 알림이 표시되기 직전에도 `goalVersion`, `runId`, `navigationId`, 정책·피드백 버전을 다시 확인한다.
- `DISMISSED`, `EXPIRED`, 무응답은 관련성 정답이 아니다.
- 실제 쿨다운과 횟수 상한은 사용자 테스트 후 설정으로 확정한다.

### 10.3 사용자 보호 원칙

- 사용자를 비난·모욕하거나 공부 의지를 단정하지 않는다.
- 실패·미지원은 복귀 경고가 아니라 상태와 해결 가능한 다음 행동으로 설명한다.
- 차단 제안은 대상 페이지·Domain, 기간, 해제 방법을 먼저 보여준다.
- YouTube·GitHub처럼 학습과 비학습 콘텐츠가 섞인 Domain 전체를 한 이벤트로 차단하지 않는다.
- 접근성 설정, 알림 빈도와 민감도 설정을 정책 입력으로 분리한다.

## 11. 캐시와 결과 적용

- 사용자 피드백은 AI 캐시보다 우선한다.
- 목표·콘텐츠 관련성 캐시와 시간 기반 흐름 결과를 분리한다.
- URL만 같은 페이지의 오래된 결과를 재사용하지 않는다.
- 목표, 모델, Prompt, 전처리, 추출기, 정책, 피드백 버전이 바뀌면 관련 캐시를 무효화한다.
- 응답 적용 전에 `goalVersion`, `runId`, `eventId`, `navigationId`를 다시 확인한다.

불일치 결과는 `STALE_EVENT`로 폐기하고 현재 탭을 덮어쓰지 않는다.

## 12. 학습 시간과 노트

시간은 Server가 시작·중지·복귀·포커스 이벤트를 이용해 겹치지 않는 구간으로 계산한다. AI는 관련성과 흐름 라벨을 제공할 수 있지만 분 단위를 추정하거나 누적값을 확정하지 않는다.

학습 노트는 회차 종료와 Server 집계 확정 후 생성한다. 다음을 구분한다.

- 자료를 확인함 vs 내용을 이해함
- 해결 자료를 열람함 vs 오류를 해결함
- 관찰된 흐름 vs AI가 제안한 다음 단계

근거가 없으면 항목을 생략하거나 정보 부족으로 표시한다.

## 13. 검증 기준

변경은 `evaluation_spec.md`의 고정 평가 세트에서 검증한다. 특히 다음은 반드시 포함한다.

- 보조 학습을 `OFF_TASK`로 오판하지 않는지
- 짧은 방문과 지속 이탈을 구분하는지
- 실패와 `UNAVAILABLE`을 이탈로 바꾸지 않는지
- 사용자 수정 후 캐시·대기 알림이 즉시 무효화되는지
- Prompt Injection과 잘못된 모델 출력이 사용되지 않는지
- ColPali 결과가 기준선을 개선하면서 개인정보·자원 예산을 충족하는지
